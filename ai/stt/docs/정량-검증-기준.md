# 음성 상호작용 정량 검증 기준

> Jira: S15P11A301-110
> 기준 장비: Jetson Orin Nano 8GB, BRIO 100 내장 마이크, 블루투스 스피커
> 대상 구성: 로컬 VAD/STT + GMS `gpt-5.4-mini` + 위험도 참고 규칙 + 사전녹음 안내
>
> 용어: [`음성-파이프라인-용어집.md`](음성-파이프라인-용어집.md)

## 1. 목적과 판정 원칙

이 문서는 모델을 골라 놓고 결과를 설명하기 위한 문서가 아니라, 테스트 전에 통과 기준을
고정하기 위한 문서다. 실제 수치는 S15P11A301-118·119·120에서 측정해 채운다.

- 평균만으로 통과시키지 않고 P50·P95·최악값과 실패 건수를 함께 기록한다.
- STT, GMS 정보 추출, 위험도 참고 규칙, 시스템 자원, 장애 대응을 분리해서 측정한다.
- 시스템 실패를 요구조자 무응답으로 계산하지 않는다.
- 같은 원본 음성을 모델별로 재사용해 비교 조건을 맞춘다.
- 기준 미달 결과를 삭제하지 않고 원본 로그와 함께 남긴다.
- 아래 기준 변경이 필요하면 측정 전에 팀 합의와 변경 사유를 기록한다.

## 3. 공통 테스트 데이터

### 3-1. 최소 데이터셋

| 구분 | 최소 구성 |
|---|---|
| 화자 | 3명 이상, 특정 화자 한 명에게 편중하지 않음 |
| 언어 범위 | 표준 한국어와 일반적인 구어체. 사투리는 현재 지원·평가 범위에서 제외 |
| 핵심 발화 | 화자당 10개 이상 |
| 소음 조건 | clean, SNR 10dB, 5dB, 0dB |
| 무음·비언어 | 무음 10개, 생활 소음 10개, 신음 10개 이상 |
| 핵심 슬롯 | 음성 응답, 응답 가능 인원, 이동 가능, 긴급 상태 자기보고 |
| 숫자 표현 | 화자 본인을 포함한 응답 가능 인원 1·2·3명과 모호한 수량 표현 포함 |

최소 STT 평가량은 `3명 × 10발화 × 4조건 = 120개`다. 같은 발화에 소음을 합성할 때는
원본 clean 파일과 SNR 생성 파라미터를 함께 보관한다.

사투리 음성·표현은 현재 모델의 성능을 보장하지 않으며 Jira 120 합격 점수에도
포함하지 않는다. 필러, 말 더듬기, 자연스러운 조사 생략은 표준 한국어 구어체
범위로 포함한다.

### 3-2. 정답 라벨

각 샘플은 다음 정답을 가진다.

```json
{
  "sampleId": "speaker01-injury01-snr05",
  "referenceText": "다리가 아프고 움직일 수 없어요",
  "expected": {
    "reportedResponsiveCount": null,
    "mobilityStatus": "NO",
    "urgentConditionReported": "UNKNOWN"
  },
  "expectedRiskLevel": "URGENT"
}
```

라벨은 모델 출력을 본 뒤 수정하지 않는다. 애매한 샘플은 평가 전에 팀원 2명이 합의하고,
합의되지 않으면 `UNKNOWN` 정답으로 분리한다.

## 4. STT·VAD 기준

### 4-1. 지표 정의

- **WER**: `(치환 + 삭제 + 삽입) / 정답 단어 수`
- **핵심 표현 보존율**: 부위, 위험요소, 숫자, 가능/불가처럼 downstream 판단에 필요한
  표현이 STT 결과에 남은 비율
- **발화 검출 재현율**: 실제 발화 중 VAD가 검출한 비율
- **비발화 오검출률**: 무음·생활 소음을 발화로 통과시킨 비율
- **RTF**: STT 처리 시간 / 입력 음성 길이

### 4-2. 통과 기준

| 항목 | 통과 기준 |
|---|---|
| clean WER | 평균 ≤ 15% |
| SNR 10dB WER | 평균 ≤ 20% |
| SNR 5dB WER | 평균 ≤ 25% |
| SNR 0dB WER | 측정값 기록, 평균 ≤ 40%를 목표로 하되 핵심 표현 기준을 우선 적용 |
| 핵심 표현 보존율 | 전체 ≥ 90%, 숫자·가능/불가 ≥ 95% |
| VAD 발화 검출 재현율 | ≥ 95% |
| 무음 오검출 | 10개 중 0건 |
| 무음+생활 소음 비발화 오검출률 | ≤ 5% |
| STT RTF | P95 ≤ 1.0 |

SNR 0dB에서 WER만 높고 핵심 표현이 보존되는 경우는 별도 기록한다. 반대로 WER가 낮아도
`불가`를 `가능`으로 바꾸거나 부상자 수를 바꾸면 치명 오류로 판정한다.

## 5. GMS 정보 추출·위험도 참고 규칙 기준

### 5-1. 반복 조건

- STT 정답 텍스트 입력과 실제 STT 출력 입력을 분리해 측정한다.
- 샘플별 GMS 호출은 최소 3회 반복한다.
- 모델명, 프롬프트 버전, 호출 시각, HTTP 상태, 토큰 또는 GMS 사용량을 기록한다.
- warm-up 호출은 지연 통계에서 제외하되 별도 로그로 남긴다.

### 5-2. 통과 기준

| 항목 | 통과 기준 |
|---|---|
| JSON 파싱 성공률 | ≥ 99% |
| 스키마 준수율 | ≥ 99% |
| 핵심 슬롯 정확도 | 전체 ≥ 90% |
| 숫자·가능/불가 슬롯 정확도 | ≥ 95% |
| 발화에 없는 슬롯 생성률 | ≤ 2% |
| 위험도 참고 규칙 정답 일치율 | ≥ 95% |
| 동일 입력 반복 일관성 | 핵심 슬롯 완전일치 ≥ 95% |
| GMS 호출 성공 시 지연 | P95 ≤ 3초 |
| GMS 오류율 | 인증·할당량 오류 제외, 일시 오류 ≤ 2% |

정확도는 슬롯별로도 공개한다. 빈 배열과 `미확인`을 정답으로 많이 넣어 전체 정확도를
부풀리지 않도록, 값이 실제 존재하는 양성 샘플의 재현율을 별도로 계산한다.

### 5-3. 치명 오류

다음 오류는 평균 정확도와 별개로 건수 `0`을 목표로 하며, 한 건이라도 나오면 원인과
완화책을 리뷰해야 한다.

- `움직일 수 없다`를 `가능`으로 반전
- 요구조자가 말하지 않은 긴급 상태 생성
- 응답 가능 인원 수를 임의 생성
- 시스템 장애를 요구조자 무응답으로 변환
- GMS가 구조 ETA 또는 최종 구조 순위를 생성

## 6. E2E·장애 대응 기준

### 6-1. 시간 구간

```text
VISION 트리거
 → 최초 안내 재생 시작
 → 청취 시작
 → STT 완료
 → GMS 완료
 → 관제 전송 완료
 → 결과 안내 재생 시작
```

각 경계의 monotonic timestamp를 남기고 다음을 계산한다.

| 지표 | 통과 기준 |
|---|---|
| 트리거→최초 안내 시작 | P95 ≤ 1초 |
| 발화 종료→STT 완료 | P95 RTF ≤ 1.0 |
| STT 완료→GMS 완료 | P95 ≤ 3초 |
| 발화 종료→관제 전송 완료 | P95 ≤ 5초 |
| 관제 전송 완료→안내 시작 | P95 ≤ 0.5초 |

블루투스 스피커의 절전 복귀로 첫 음절이 잘리는 경우는 지연 통과 여부와 별개로 실패 처리한다.

### 6-2. 장애 시나리오

| 시나리오 | 최소 반복 | 통과 기준 |
|---|---:|---|
| 정상 청취 후 요구조자 무응답 | 5회 | `NO_RESPONSE_OBSERVED` 기록 100%, 시스템 장애와 혼동 0건 |
| 세션 전 네트워크 단절 | 5회 | 신규 STT 0회, 안전 안내 100%, 전송 대기 이벤트 100% |
| STT 후 GMS 타임아웃 | 5회 | 제한 재시도 후 33-8 폴백 100% |
| GMS 401/403 | 3회 | 오프라인으로 오분류 0건, 설정 장애 보고 100% |
| GMS 429/5xx | 각 3회 | 정책에 맞는 재시도·폴백 100% |
| 마이크 분리 | 5회 | 요구조자 무응답 분류 0건, 장치 오류 보고 100% |
| 관제 전송 실패 | 5회 | "전달했습니다" 재생 0회, 전송 대기 문구 100% |
| 연속 음성 세션 | 30회 | 완료율 ≥ 95%, 프로세스 비정상 종료 0건 |

## 7. Jetson 자원·통합 기준

측정은 음성 단독과 `비전 → 비전+SLAM → 비전+SLAM+음성`을 같은 전원 모드에서 순서대로
진행한다. 실제 주행은 정지 상태 통합 검증을 통과한 뒤에만 수행한다.

| 항목 | 통과 기준 |
|---|---|
| OOM 또는 프로세스 강제 종료 | 0건 |
| 음성 처리 피크 시 available RAM | ≥ 1GB |
| 음성 세션 전후 지속적인 swap 증가 | 세션 종료 60초 후 증가량 ≤ 256MB |
| 열 스로틀링 | 0건 |
| 음성 추가 후 비전 FPS 저하 | 기준 대비 ≤ 10% |
| 30회 세션 후 메모리 증가 | 초기 안정 상태 대비 ≤ 10% |

RAM은 `tegrastats` 1초 로그의 피크뿐 아니라 시작 전 baseline, 세션 종료 후 60초 값을 함께
남긴다. 기존 로컬 LLM 5.62GB 기록과 GMS 구성은 동일한 Jetson·전원 모드·GUI 상태에서 비교한다.

최소 공통 필드:

```text
runId, timestamp, gitCommit, device, powerMode, sampleId, speakerId, snrDb,

wer, keyTermCorrect, gmsStatus, schemaValid, slotCorrect, hallucinatedSlots,
```

원본 로그와 CSV에는 GMS 키, 인증 헤더, 요구조자 개인정보를 저장하지 않는다. 발표·포트폴리오
자료에는 화자 식별자를 익명화하고 집계값만 사용한다.

## 9. 현재 벤치 코드의 측정 가능 범위와 보완점

현재 [`bench/pipeline_bench.py`](../bench/pipeline_bench.py)는 다음만 제공한다.

- STT 단일 실행 시간
- GMS 평균·최소·최대 지연
- 반복 결과의 구조화 필드·위험도 참고값 일관성
- 원본·요약 CSV

최종 검증 전에 필요한 보완:

1. 정답 transcript와 슬롯 라벨을 읽어 WER·슬롯 정확도를 계산한다.
2. STT도 조건별·화자별로 반복하고 RTF를 기록한다.
3. 평균·최소·최대에 P50·P95와 오류율을 추가한다.
4. 핵심 슬롯 완전일치와 발화에 없는 값 생성 여부를 비교한다.
5. 단계별 monotonic timestamp로 E2E를 기록한다.
6. SED 기반 `non_ok_outcome()`이 STT 실패를 무응답으로 만드는 기존 경로를 최종 평가에서 제거한다.
7. tegrastats 로그와 `runId`를 연결한다.

위 보완은 S15P11A301-118·119·120의 구현 범위로 나눠 수행한다. 현재 벤치 결과만으로
STT 품질이나 GMS 전환 효과가 검증됐다고 결론 내리지 않는다.

## 10. 최종 판정

- **PASS**: 모든 필수 기준 충족, 치명 오류 0건
- **CONDITIONAL**: 비필수 목표 한계치만 미달하고 완화책·재시험 일정이 승인됨
- **FAIL**: 필수 기준 미달, 치명 오류 발생, 로그 누락 또는 조건 불일치

최종 보고서에는 성공 수치뿐 아니라 실패 샘플, 제외 샘플과 제외 사유, 실행 명령,
Git commit, 장비 상태를 함께 첨부한다.
