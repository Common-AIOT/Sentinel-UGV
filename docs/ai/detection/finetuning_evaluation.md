# Detect 파인튜닝 평가 — 미채택 결정

사람 탐지 모델(`yolo26n`)을 쓰러진 사람에 맞춰 파인튜닝하려 한 시도와 그 결과입니다.
**결론은 미채택이며, 사전학습 가중치를 그대로 씁니다.** (Jira: S15P11A301-94)

> **한 줄 요약** 데이터 3종 × 학습 방식 4종을 교차 평가한 결과, **사전학습을 이긴 조합이
> 하나도 없었습니다.** COCO 118,000장의 다양성을 수천~수만 장으로 대체할 수 없습니다.

---

## 1. 무엇을 풀려고 했나

**쓰러진 사람을 "사람"으로 탐지하는 비율을 높이는 것**입니다. 쓰러졌는지 판정하는 것은
별개이며 규칙 기반(`src/posture_classifier.py`)이 담당합니다.

```
Detect  (학습 대상)   쓰러진 사람을 사람으로 찾는가
Posture (규칙 기반)   찾은 사람이 쓰러진 자세인가      ← 학습 안 함
```

착수 근거는 사전학습 모델의 자세별 격차였습니다. 같은 클립·같은 조건에서 측정했습니다.

| 구간 | 탐지율 |
|---|---|
| 서 있음 | 88.0% |
| 누움 | 74.0% |

**14%p 격차**를 학습으로 메우는 것이 목표였습니다.

---

## 2. 결과 — 교차 평가

모델이 학습한 데이터와 **다른** 데이터에서의 성능이 진짜 일반화 성능입니다.
자기 도메인 숫자는 외운 것과 구분되지 않습니다.

### E-FPDS test (959장, 저자 제공 held-out)

| 모델 | mAP50 | mAP50-95 | 재현율 | 정밀도 | |
|---|---|---|---|---|---|
| **사전학습 `yolo26n`** | **0.8992** | **0.6057** | **0.8157** | 0.9342 | |
| E-FPDS 동결 | 0.8584 | 0.4594 | 0.7715 | 0.8352 | 자기 도메인 |
| E-FPDS 동결+저LR | 0.8393 | 0.4302 | 0.7492 | 0.8047 | 자기 도메인 |
| E-FPDS 전체 | 0.8040 | 0.4137 | 0.6798 | 0.8643 | 자기 도메인 |
| 71550 전체 | 0.1731 | 0.0615 | 0.2064 | 0.3760 | **교차** |

### AI-Hub 71550 val (영상 프레임 11,350장, 관절에서 유도한 정답)

| 모델 | mAP50 | mAP50-95 | 재현율 | 정밀도 | |
|---|---|---|---|---|---|
| **사전학습 `yolo26n`** | **0.9682** | 0.7124 | 0.9077 | **0.9529** | |
| 71550 전체 | 0.9638 | **0.7853** | **0.9152** | 0.9314 | 자기 도메인 |
| E-FPDS 동결 | 0.8295 | 0.4435 | 0.7224 | 0.8860 | 교차 |
| E-FPDS 동결+저LR | 0.7282 | 0.3580 | 0.6959 | 0.7401 | 교차 |
| E-FPDS 전체 | 0.5922 | 0.3265 | 0.5840 | 0.7117 | 교차 |

### 읽는 법

- **교차 칸에서 사전학습을 이긴 모델이 없습니다.**
- **71550 모델이 과적합의 전형입니다** — 자기 도메인 0.9638 → 교차 **0.1731**.
  80%p 넘게 무너집니다.
- 다만 71550 모델은 **자기 도메인에서 mAP50-95와 재현율이 사전학습보다 높습니다.**
  즉 "그 환경 전용 모델"로는 작동합니다. 문제는 다른 곳에서 못 쓴다는 것이고,
  재난 현장은 어디일지 알 수 없습니다.
- **학습률을 낮춰도 나아지지 않았습니다.** 저LR(0.8393)이 기본 LR 동결(0.8584)보다
  낮았습니다. "조금만 움직이면 덜 망가진다"는 가설은 성립하지 않았습니다.

## 3. 시도한 것 전부

| # | 데이터 | 방식 | 결과 |
|---|---|---|---|
| 1 | 71550 쓰러짐 34,488장 | 전체 갱신 | 기각 |
| 2 | + 서 있는 사람 25,540장, 라벨 보강 | 전체 갱신 | 기각 |
| 3 | E-FPDS 4,704장 (12개 장소) | 전체 갱신 | 기각 |
| 4 | E-FPDS | **backbone 동결** | 기각 |
| 5 | E-FPDS | 동결 + **lr0 0.0005, warmup 0** | 기각 |

2번은 별도 원인 규명을 거쳤습니다. 71550 라벨은 쓰러지는 사람 한 명만 표시하고 같은
화면의 점원은 라벨이 없어 **배경으로 학습**되고 있었습니다(train 29.2%, val 30.0%의
프레임에 해당). `scripts/augment_labels.py`로 채웠으나 결과는 바뀌지 않았습니다.

### 시도하지 않은 것

- **COCO person 혼합(replay)** — 문헌이 권하는 정공법이나 데이터 확보 시간이 부족했습니다
- **Adapter / self-distillation** — 연구 단계 기법, 일정 밖
- **단계적 동결 해제** — 동결이 이미 실패해 우선순위에서 밀렸습니다

## 4. 평가 방법의 함정 — 세 번 잘못 판단했습니다

**이 절이 이 문서에서 가장 중요합니다.** 다시 시도하는 사람이 같은 함정에 빠지지
않도록 남깁니다.

### 함정 1 — 같은 도메인 val만 보면 성공처럼 보인다

1차 학습의 자체 val 성적은 **mAP50 0.993, 재현율 97.7%**였습니다. 그 숫자만 보고
성공으로 보고할 뻔했습니다. 같은 시점에 다른 도메인 성적은 **0%**였습니다.

→ **반드시 학습에 쓰지 않은 도메인에서 재야 합니다.**

### 함정 2 — confidence 고정으로 재면 성능 붕괴로 오독한다

`conf=0.50` 고정으로 "사람이 잡혔나"를 셌습니다. 파인튜닝은 confidence 분포를
바꾸므로, 같은 사람을 0.45로 잡으면 미탐으로 집계됩니다.

| conf | 사전학습 | 동결 파인튜닝 |
|---|---|---|
| 0.50 | 96.7% | **0.0%** |
| 0.15 | 96.7% | 86.7% |
| 0.01 | 96.7% | 100.0% |

**모델이 못 잡은 게 아니라 점수 눈금이 바뀐 것**이었습니다. 이 발견으로 한 번
결론을 철회했고, mAP(임계값 무관)로 다시 재서 같은 결론에 도달했습니다.

→ **모델 비교는 mAP처럼 임계값에 무관한 지표로 합니다.**
→ 파인튜닝 모델을 실제로 쓰려면 `detector.confidence` 재조정이 별도로 필요합니다.

### 함정 3 — 프레임당 재현율은 운영 지표가 아니다

우리 시스템은 **1초 안정 관측**으로 확정합니다. 15 FPS면 한 사람에게 15번의 기회가
있습니다. 프레임당 재현율 +3%p는 실제 운영에서 거의 의미가 없습니다.

이 때문에 **입력 해상도 상향(640→960)도 채택하지 않았습니다.** 프레임당 재현율은
+3.4%p 올랐지만(0.8157→0.8500), 추론 시간이 40% 늘어 FPS가 떨어집니다. FPS 하락은
프레임 간 이동량을 키워 ByteTrack 연결을 어렵게 하므로 **손해가 더 큽니다.**

→ **여러 프레임을 보는 구조에서는 "관측 구간 동안 한 번이라도 잡았나"가 옳은 지표입니다.**
→ 그 측정은 정지 이미지로 불가능하며, 영상 기반 평가 도구가 아직 없습니다.

### 부수 확인 — TTA는 쓸 수 없습니다

```
WARNING Model does not support 'augment=True', reverting to single-scale prediction.
```

YOLO26은 end2end 구조라 test-time augmentation 경로가 없습니다.

## 5. 재현 방법

```bash
# E-FPDS 변환 (test는 배포 조건상 기본 제외)
python scripts/convert_efpds.py --src <E-FPDS/raw> --out data/efpds
python scripts/convert_efpds.py --src <E-FPDS/raw> --out data/efpds_test --include-test

# 71550 변환
python scripts/convert_71550.py --xml-dir <TL_..._전도> --video-dir <TS_..._전도> \
    --out data/processed --resume
python scripts/convert_71550.py --xml-dir ... --video-dir ... --out data/processed --standing
python scripts/augment_labels.py --root data/processed --split train

# 학습
python scripts/train_detect.py --data configs/dataset_efpds.yaml --epochs 10 \
    --name efpds-frozen --freeze 10

# 교차 평가
python scripts/compare_models.py
```

측정 환경: RTX 4050 Laptop 6GB, `imgsz=640`, `seed=42`, 10 epoch.
E-FPDS 1 epoch 약 2분, 71550(60,028장) 1 epoch 약 25분.

### E-FPDS 이용 조건 (준수 필수)

- **인용 의무**
  > Fallen People Detection Capabilities Using Assistive Robot.
  > S. Maldonado-Bascón et al. *Electronics* 2019.
- **test split은 결과 보고 전용** — *"strictly for reporting of results alone"*.
  학습에 사용하지 않았습니다.
- 원본 데이터는 저장소에 커밋하지 않습니다(`.gitignore`의 `data/`).

E-FPDS는 **카메라 높이 76cm의 이동 로봇** 촬영이라 우리 UGV 시점과 가장 가깝습니다.
파인튜닝은 채택하지 않았지만 **평가 자산으로서는 계속 유효**합니다.

## 7. 다시 시도한다면

파인튜닝을 재검토할 조건입니다.

1. **COCO person을 혼합**할 것 — 유일하게 안 해본 정공법입니다
2. **영상 기반 평가 도구를 먼저 만들 것** — 함정 3 참고. 프레임 단위 지표로는
   채택 여부를 판단할 수 없습니다
3. **배치 환경 영상을 확보할 것** — 실제 UGV 카메라로 찍은 복도 영상이 있으면
   평가의 신뢰도가 근본적으로 달라집니다

그리고 **사전학습 `yolo26n`이 이미 강하다**는 점을 전제로 삼아야 합니다. 논문 저자들이
YOLOv3에서 파인튜닝 효과를 본 것은 2022년 기준이며, 그 격차를 최신 사전학습이 이미
메웠을 가능성이 큽니다.
