# ReID inference (configs/tracker_sentinel.yaml with_reid: True).
# ONNX Runtime is used ONLY for the ReID model. Detect and Pose run on PyTorch,
# so this is not needed when ReID is off.
#
# Only the development-PC profile turns ReID on. The Jetson profile
# (configs/tracker_jetson.yaml) has with_reid: False, so the robot does not
# need this package at all unless someone re-enables ReID there.
#
# CPU vs GPU matters a lot here. ReID runs once per person per frame, so a CPU
# fallback costs a large share of the frame budget. Verify with:
#
#     python -c "import onnxruntime as ort; print(ort.get_available_providers())"
#
# CUDAExecutionProvider or TensorrtExecutionProvider must appear.
#
# ⚠️ Jetson (aarch64) is intentionally excluded from the marker below.
#    Two reasons. First, the robot does not run ReID, so it does not need this.
#    Second, the PyPI `onnxruntime-gpu` wheel does not cover aarch64, and installing
#    plain `onnxruntime` there would silently give a CPU-only build that looks fine
#    but is slow. If ReID is ever re-enabled on the Jetson, install a JetPack-matched
#    wheel from NVIDIA's Jetson index instead:
#        https://elinux.org/Jetson_Zoo#ONNX_Runtime
#
#    Note the marker is `!= "aarch64"`, not `== "x86_64"`. Windows reports
#    platform_machine as "AMD64" while Linux reports "x86_64", so an equality
#    check on x86_64 silently skips the development PC.
#
#    Development PC has both `onnxruntime` and `onnxruntime-gpu` at 1.23.2.
onnxruntime-gpu; platform_machine != "aarch64"
