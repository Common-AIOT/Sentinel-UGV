# 사전녹음 안내 음성 제작·검증

> Jira: S15P11A301-114
> 장비: BRIO 100 마이크, Bluetooth 스피커
> 코드 기준: `sentinel_voice/guide_audio.py`

## 1. 목적과 안전 원칙

Jetson에는 TTS 모델을 설치하지 않는다. 승인된 문구를 사람이 녹음한 PCM WAV로
재생하여 RAM 사용과 자유 생성 문장의 위험을 줄인다.

- 등록되지 않은 문장은 재생하지 않는다.
- WAV가 없거나 잘못돼도 동적 TTS로 대체하지 않는다.
- 재생 실패와 마이크 무응답은 서로 다른 오류다.
- 관제 전송 성공이 확인되지 않으면 "전달했습니다" 파일을 재생하지 않는다.
- 요구조자의 절대 위치가 관제에 전달됐다고 안내하지 않는다.
- 탐사 재개 Closing은 관제 전송 성공과 Mission Manager의 재개 승인이 모두 확인된 뒤 재생한다.
- S15P11A301-116 전까지 정상 종료 안내는 `REPORT_PENDING`을 사용한다.

## 3. MiniMax 생성 입력

문서의 승인 문구 의미는 유지하면서 다음 pause 태그를 사용한다. Sound tag와
효과음은 VAD·STT 재유입 가능성이 있어 넣지 않는다.

```text
탐사 로봇입니다.<#0.3#>구조 요청을 돕겠습니다.<#0.3#>제 말이 들리면 대답해 주세요.

지금 주변에 대화할 수 있는 분이 모두 몇 명인가요?

지금 스스로 움직일 수 있나요?

지금 어디가 가장 불편한가요?<#0.3#>숨쉬기 어렵거나 피가 많이 나면 말씀해 주세요.

제 말이 들리면 다시 한번 대답해 주세요.

목소리가 잘 들리지 않았습니다.<#0.3#>천천히 다시 말씀해 주세요.

구조 요청을 관제에 전달하고 있습니다.<#0.35#>잠시만 기다려 주세요.

구조 요청이 관제에 전달되었습니다.

구조 요청이 관제에 전달되었습니다.<#0.4#>다른 구역을 확인하기 위해 탐사를 계속하겠습니다.

통신 연결을 확인하고 있습니다.<#0.35#>연결되는 대로 구조 요청을 전달하겠습니다.
```

모든 파일은 같은 MiniMax 모델, Voice ID, 속도, 피치, 음량과 감정 설정으로
생성하고 설정값을 검수 기록에 남긴다.

### 최종 WAV 생성 이력

| 항목 | 적용값 |
|---|---|
| 생성 서비스 | MiniMax |
| 모델 | `speech-2.8-hd` |
| Voice | `Brave Female Warrior` |
| Speed | `1.1` |
| Pitch | `0` |
| Volume | `1.75` |
| Emotion | 사용하지 않음 |
| Sound tag | 사용하지 않음 |
| Pause tag | 사용하지 않음 |
| 생성일 | 2026-07-28 |
| 로컬 청취 | 완료 |
| BRIO 100·Bluetooth 실장 검증 | 보류 — 실제 장착 후 수행 |

위 설정으로 만든 MiniMax 원본을 FFmpeg로 16kHz, mono, PCM 16-bit,
목표 RMS -20dBFS의 운영 WAV로 변환했다. 앞 절의 pause 태그는 제작 시
검토한 권장 입력 예시이며 이번 최종 생성본에는 적용하지 않았다.

## 4. MiniMax 원본 파일명

MiniMax에서 다운로드한 원본 WAV는 `ai/stt/`에 다음 이름으로 저장한다.
원본 `mini_*.wav`는 변환 입력이며 Git 커밋 대상이 아니다.

```text
mini_intro.wav
mini_ask_count.wav
mini_ask_mobility.wav
mini_ask_urgent.wav
mini_retry_no_response.wav
mini_retry_unclear.wav
mini_report_pending.wav
mini_report_succeeded.wav
mini_report_succeeded_departure.wav
mini_network_wait.wav
```

Miniforge Prompt에서 다음 명령으로 10개를 일괄 변환한다.

```bat
conda activate sentinel-audio
cd C:\Users\SSAFY\Desktop\S15P11A301\ai\stt
python -m tools.convert_guide_assets --source-dir . --force
```

변환 도구는 원본을 수정하지 않고 `assets/guide_*.wav`를 생성한 뒤 각 파일의
형식과 레벨을 즉시 검사한다. `--force`는 이전 후보 WAV를 새 최종본으로
교체하기 위해 사용한다.

## 5. 녹음·편집 규격

1. 조용한 공간에서 한 명의 화자가 차분하고 또렷하게 녹음한다.
2. 공포를 키우는 억양이나 지나치게 빠른 속도를 피한다.
3. 파일 앞뒤 불필요한 침묵을 제거하되 첫 음절이 잘리지 않게 한다.
4. mono, 16,000Hz, PCM 16-bit WAV로 내보낸다.
5. peak는 -1dBFS 이하, RMS는 -32~-12dBFS 범위로 맞춘다.
6. 표의 파일명 그대로 `ai/stt/assets/`에 저장한다.

원본 편집 프로젝트나 개인정보가 포함된 녹음본은 저장소에 넣지 않는다. 저장소에는
승인된 최종 WAV만 포함한다.

## 6. 자동 검사

Miniforge Prompt에서 실행한다.

```bat
conda activate sentinel-audio
cd C:\Users\SSAFY\Desktop\S15P11A301\ai\stt
python -m tools.validate_guide_assets --report results\guide-assets.json
```

모든 파일이 `[OK]`여야 한다. 검사는 파일 존재 여부, mono, PCM 16-bit, 16kHz,
길이, peak와 RMS를 확인한다. 실제로 문구가 정확한지와 음질이 좋은지는 사람이
청취하여 별도로 확인해야 한다.

## 7. 로컬 청취 검수표

각 파일을 헤드폰과 예정 Bluetooth 스피커로 3회씩 듣고 기록한다.

| 항목 | 합격 조건 |
|---|---|
| 문구 정확성 | 표의 문구와 한 글자도 다르지 않음 |
| 명료성 | 3회 모두 내용을 다시 듣지 않고 이해 |
| 첫·끝 음절 | 잘림 없음 |
| 잡음·클리핑 | 뚜렷한 잡음, 찢어짐, 팝 노이즈 없음 |
| 음량 일관성 | 파일 전환 시 급격한 음량 차이 없음 |
| 말투 | 차분하며 구조 확정·의료 진단으로 오해되지 않음 |

## 8. BRIO 100·Bluetooth 스피커 실장 검증

Jetson에서 `docs/오디오-입출력-검증.md`에 따라 장치를 먼저 확인한다.

> 현재 상태: 로컬 청취와 자동 WAV 검사는 완료했다. 아래 실장 시험은 아직
> 수행하지 않았으며, 결과를 추정해 합격 처리하지 않는다.

1. BRIO 100을 입력 장치로, Bluetooth 스피커를 출력 장치로 선택한다.
2. 각 안내 WAV를 3회 재생하여 끊김과 지연을 기록한다.
3. 스피커와 BRIO 100 간 거리를 실제 장착 거리로 고정한다.
4. 안내 재생 중에는 마이크 청취를 시작하지 않는다.
5. 재생 종료 후 300ms 뒤 청취를 시작하고 로봇 음성이 STT에 다시 들어오는지 확인한다.
6. 에코가 검출되면 스피커 음량·방향·거리 조정 후 재시험한다.

권장 합격 기준:

- 파일별 재생 성공률: 3/3
- 재생 시작 지연: P95 0.5초 이하
- 끊김: 0회
- 로봇 안내 음성의 STT 재유입: 0회
- 장치 오류를 무응답으로 기록한 건수: 0건

300ms는 초기 검증값이며 실제 장비 결과에 따라 조정한다. 고정 전에 스피커 볼륨,
장착 거리, 주변 소음과 Git commit을 함께 기록한다.

## 9. Closing과 탐사 재개 계약

`REPORT_SUCCEEDED_DEPARTURE`는 음성 모듈이 임의로 선택하지 않는다.

```text
관제 전송 성공
AND Mission Manager의 탐사 재개 승인
→ REPORT_SUCCEEDED_DEPARTURE 재생
→ 재생 완료 확인
→ 주행 안전 확인
→ 탐사 재개
```

관제 전송만 성공하고 탐사 재개가 승인되지 않았다면 `REPORT_SUCCEEDED`만
재생한다. 전송 성공 전에는 `REPORT_PENDING` 또는 `NETWORK_WAIT`을 사용한다.
음성 모듈은 모터를 직접 제어하지 않는다.

로봇이 보유한 상대 좌표는 요구조자의 명확한 절대 위치를 보장하지 않으므로,
어떤 안내 문구도 "현재 위치가 관제에 전달되었습니다"라고 말하지 않는다.

## 10. 결과로 제출할 파일

```text
results/guide-assets.json       자동 형식·레벨 검사 결과
guide_playback_console.log      Jetson 재생 로그
audio_io_report.json            BRIO 100·스피커 장치 및 녹음 레벨
114-guide-review.md             파일별 3회 청취·에코 검수 결과
```

`results/`와 로그는 기본적으로 커밋하지 않는다. 팀 공유가 필요하면 GMS 키,
장치 식별정보, 사람 목소리의 개인정보 포함 여부를 확인한 뒤 별도 증적 저장소에 올린다.
