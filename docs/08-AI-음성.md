# 33. 피해자 음성 상호작용 설계 [확정]

## 33.1 한 줄 결론

현재 운영 구조는 **Jetson 로컬 VAD → L40S FastAPI Qwen3-ASR → GMS
`gpt-5.4-mini` 구조화 → 규칙 기반 위험도 → 승인된 사전 녹음 WAV 재생**이다.

```mermaid
flowchart LR
    encounter["VISION Encounter"] --> guide["사전 녹음 안내"]
    guide --> mic["BRIO 100 마이크"]
    mic --> vad["Jetson Silero VAD"]
    vad --> asr["L40S FastAPI\nQwen3-ASR-1.7B"]
    asr --> guard["환각·빈 전사 가드"]
    guard --> gms["GMS gpt-5.4-mini\n3필드 구조화"]
    gms --> rule["규칙 기반 위험도"]
    rule --> report["관제 보고 인계"]
    report --> closing["종료 안내 후 탐사 재개"]
```

| 단계 | 최종 선택 | 배치 |
|---|---|---|
| 입력 | BRIO 100 내장 마이크 | Jetson |
| 안내 | 승인된 사전 녹음 WAV 6개 | Jetson |
| VAD | Silero VAD | Jetson |
| STT | `Qwen/Qwen3-ASR-1.7B` | L40S Device3 FastAPI |
| 정보 추출 | GMS `gpt-5.4-mini` | 외부 API |
| LLM 장애 폴백 | 제한된 키워드 파서 | Jetson |
| 위험도 | `voice-risk-v1.1` 명시 규칙 | Jetson |
| 출력 | 블루투스 A2DP 스피커 | Jetson |

동적 TTS, Jetson 로컬 Whisper, Jetson 로컬 LLM은 운영 경로가 아니다. DeepFilterNet은
관제 청취본 후처리용이며 STT 입력 앞에 연결하지 않는다.

## 33.2 안전 경계

- LLM은 의료 진단, 구조 우선순위 확정, 주행 명령을 하지 않는다.
- LLM은 인원 수, 이동 가능 여부, 긴급 상태 언급만 정해진 JSON으로 추출한다.
- 위험도는 추출값을 입력으로 하는 명시적 규칙이며 관제 검토용 참고값이다.
- 로봇은 요구조자에게 위험 등급을 말하지 않는다.
- STT 실패를 무응답으로 기록하지 않는다.
- 네트워크가 끊긴 상태에서는 신규 음성 세션을 시작하지 않는다.
- 이미 STT가 끝난 뒤 GMS만 실패한 경우에만 키워드 폴백으로 축소 보고한다.
- 원음, API 키와 인증 헤더를 일반 애플리케이션 로그에 남기지 않는다.

## 33.3 대화 상태 머신

질문은 부상 우선 순서로 한 번씩 진행한다.

| 단계 | 파일 | 승인 안내 문구 |
|---|---|---|
| `INTRO` | `guide_intro.wav` | 구조 로봇입니다. 들리면 대답해 주세요. |
| `URGENT` | `guide_ask_urgent.wav` | 다친 곳이 있으십니까? |
| `MOBILITY` | `guide_ask_mobility.wav` | 움직일 수 있습니까? |
| `COUNT` | `guide_ask_count.wav` | 주변에 다른 인원이 있습니까? |
| `RETRY_NO_RESPONSE` | `guide_retry_no_response.wav` | 제 말이 들린다면 대답해주십시오. |
| `REPORT_SUCCEEDED_DEPARTURE` | `guide_report_succeeded_departure.wav` | 구조 요청이 전달되었습니다. 다시 탐색을 시작합니다. |

INTRO에서 무응답이면 한 번만 재질문한다. 이후 값이 확정되지 않아도 같은 질문을 반복하지
않고 `UNKNOWN`으로 진행해 대화를 끝낸다.

### 턴 결과 4분류

| 상태 | 음성 감지 | STT | 구조화 | 의미 |
|---|---:|---:|---:|---|
| `NO_RESPONSE` | 아니오 | — | — | 실제 무응답 |
| `VOICE_DETECTED_STT_FAILED` | 예 | 실패 | — | 사람은 답했지만 전사 실패 |
| `ANSWER_UNSTRUCTURED` | 예 | 성공 | 실패 | 문장은 있으나 필드 확정 불가 |
| `ANSWER_STRUCTURED` | 예 | 성공 | 성공 | 필드 기록 가능 |

반문과 맥락을 고려한다. 예를 들어 “다리 다쳤는데 움직일 수 있겠냐고요”는 질문 맥락상
이동 불가를 뜻하므로 `mobilityStatus=NO`다. 단순 키워드 `움직일 수`만 보고 `YES`로
판정하지 않는다.

## 33.4 보고 계약

세션 보고의 기준 필드는 다음과 같다.

```json
{
  "responseScope": "GROUP",
  "anyResponseDetected": true,
  "reportedResponsiveCount": 2,
  "reportedCountStatus": "SELF_REPORTED_GROUP_COUNT",
  "countConfidence": null,
  "mobilityStatus": "NO",
  "urgentConditionReported": "YES",
  "operatorReviewRequired": true,
  "terminationReason": "NORMAL"
}
```

| 필드 | 책임 주체 |
|---|---|
| `anyResponseDetected` | VAD·상태 머신 |
| `reportedResponsiveCount` | GMS 또는 키워드 추출 결과 |
| `mobilityStatus` | GMS 또는 키워드 추출 결과 |
| `urgentConditionReported` | GMS 또는 키워드 추출 결과 |
| `terminationReason` | 상태 머신 |
| `riskLevel`, `riskReasons` | 규칙 엔진 |
| 최종 구조 판단 | 관제자 |

`UNKNOWN`은 질문했지만 값이 확정되지 않았다는 뜻이다. `null`은 해당 필드에 값 자체가
적용되지 않거나 제공되지 않았다는 뜻이다. 여러 사람이 있는 경우 자동 화자 분리를 하지
않고 `responseScope=GROUP`으로 전달한다.

관제 ACK를 기다리는 구조는 사용하지 않는다. 보고는 전송 어댑터의 성공·대기 상태로 인계하고,
종료 안내는 한 번만 재생한 뒤 Mission Manager 계약에 따라 탐사를 재개한다.

## 33.5 GPU ASR 서버

### API 계약

```http
GET /health
POST /v1/asr
Authorization: Bearer <ASR_API_KEY>
Content-Type: multipart/form-data
```

지원 입력은 WAV/FLAC/OGG, mono/stereo, 8~48kHz이며 기본 제한은 30초·16MiB다. 공유
GPU 동시 추론 기본값은 1건이다.

| HTTP | 오류 코드 | 클라이언트 처리 |
|---:|---|---|
| 401 | `UNAUTHORIZED` | 키·환경 설정 확인, 재시도 안 함 |
| 413 | `AUDIO_TOO_LARGE`, `AUDIO_TOO_LONG` | 입력 계약 수정 |
| 415 | `UNSUPPORTED_AUDIO_TYPE`, `INVALID_AUDIO` | 녹음·인코딩 확인 |
| 422 | `UNSUPPORTED_LANGUAGE`, `UNSUPPORTED_SAMPLE_RATE` | 요청 계약 수정 |
| 429 | `ASR_OVERLOADED` | 제한 재시도 후 STT 실패 기록 |
| 503 | `MODEL_NOT_READY`, `MODEL_INFERENCE_FAILED` | health 확인 후 제한 재시도 |

오류 응답은 `error.code`, `message`, `request_id`, `retryable`을 포함한다. Jetson은 어떤
서버 오류도 `NO_RESPONSE`로 바꾸지 않는다.

### L40S 실행

```bash
cd /path/to/S15P11A301/ai/voice
python3.12 -m venv .venv-gpu-asr
source .venv-gpu-asr/bin/activate
python -m pip install -U pip
python -m pip install -r asr_server/requirements.txt

cp asr_server/.env.example .env.gpu-asr
set -a
source .env.gpu-asr
set +a
python -m asr_server
```

`ASR_CUDA_VISIBLE_DEVICES=3`은 프로세스 내부 `cuda:0`을 물리 Device3에 연결한다.

```bash
nvidia-smi -i 3
curl -sS http://127.0.0.1:18100/health
```

기본 바인딩은 `127.0.0.1:18100`이다. Jetson이 직접 접근하는 격리 개발망 시험에서만
`0.0.0.0`과 평문 HTTP 예외를 사용한다. 장기 운영은 TLS reverse proxy, VPN 또는 승인된
SSH 터널 뒤에 둔다. 포트를 인터넷에 직접 공개하지 않는다.

### 보안

- Bearer 또는 `X-API-Key` 인증을 필수로 한다.
- `.env.gpu-asr`와 실제 키는 Git에 넣지 않는다.
- 업로드 임시 파일은 성공·실패와 무관하게 요청 종료 시 삭제한다.
- 원음과 전사문을 ASR 서버 로그에 남기지 않는다.
- 타 팀이 공유 GPU를 사용 중이면 프로세스를 임의로 종료하지 않는다.

## 33.8 실측 결과와 모델 선정

### ASR: Qwen3-ASR-1.7B 채택

L40S Device3에서 동일 합성 음성 9건을 모델별 3회 실행한 결과다.

| 모델 | micro CER | micro WER | 핵심 표현 | 위험·안전 뒤집힘 | P50 / P95 | RTF | VRAM |
|---|---:|---:|---:|---:|---:|---:|---:|
| Qwen3-ASR-1.7B | **0.0000** | **0.0000** | 100% | 0 | 260.667 / 425.847ms | 0.1024 | 5,014MiB |
| faster-whisper turbo | 0.0291 | 0.0968 | 비교 열세 | 별도 기록 | — / 367.649ms | — | 2,170MiB |

Whisper turbo가 더 가볍고 약간 빠르지만 정확도와 핵심 표현 보존에서 Qwen이 우세해 운영
모델로 선정했다. 이 코퍼스는 합성 스모크 규모가 작으므로 현장 마이크·소음 코퍼스에서
같은 결론이 유지되는지 별도 검증한다.

과거 KsponSpeech에서 로컬 Whisper small을 측정한 값은 clean CER 0.141, SNR 0dB CER
0.366이었다. 이는 한국어 일반 코퍼스 기준이지 재난 현장 성능이 아니며 현재 원격 Qwen
운영 성능으로 재사용하지 않는다.

### LLM: GMS gpt-5.4-mini 유지

프롬프트 v2 회귀에서 20문장 60필드 100%, 안전 일치 20/20, 위험·안전 반전 0건,
P95 1.78초를 기록했다. 외부 생성 표준 한국어 문항까지 확장한 평가에서도 비용·지연·안전
균형이 가장 좋아 운영 모델로 유지했다.

L40S 로컬 `Qwen3.5-4B` shadow는 P95 7,616.67ms로 GMS 2,017.06ms보다 느렸고 치명
오분류 1건이 있어 전환하지 않았다. Claude Opus 계열은 일부 정답이 개선됐지만 비용과 P95가
증가해 채택하지 않았다. 사투리는 현재 합격 범위 밖이며 표준 한국어와 일반 구어체만 보장한다.

### 안내 음성: 사전 녹음 유지

다국어 TTS 후보를 L40S에서 비교했으나 질문이 고정돼 있고 실제 운영 음성의 일관성·검수·즉시
재생이 더 중요하므로 기존 사전 녹음 자산을 유지했다. 런타임 TTS 모델은 설치하지 않는다.
생성 모델 비교 결과는 의사결정 이력일 뿐 운영 의존성이 아니다.

필수 자산은 `ai/voice/assets`의 intro, urgent, mobility, count, retry, closing 계열 WAV다.
배포 전에 `python -m tools.validate_guide_assets`로 형식과 누락을 검사하고 사람이 실제
스피커로 청취 검수한다.

### 메모리 결정

과거 Jetson 로컬 Whisper와 로컬 3B LLM 조합은 8GB 메모리에서 다른 로봇 기능과 경쟁했다.
로컬 `qwen2.5:3b`는 page cache 압박 시 GPU 로드 실패도 관측됐다. 현재는 STT 모델을 L40S,
LLM을 GMS로 이동하고 Jetson에는 VAD·오디오·HTTP 클라이언트만 남겨 메모리 위험을 줄였다.
다만 YOLO·SLAM·Nav2·영상까지 함께 실행한 통합 peak는 실제 Jetson에서 다시 측정해야 한다.

## 33.9 소음과 잡음 제거

DeepFilterNet은 **관제자가 듣는 녹음 후처리에는 채택**, **STT 전처리에는 미채택**한다.

| 관측 | 결과 |
|---|---|
| 합성 A/B 108조건 | 원본 승 58, denoise 승 16, 무승부 34 |
| CER 중앙값 | 원본 0.467, denoise 0.667 |
| 처리 비용 | 60초 음성 약 1초, RTF 0.017 수준 |
| 실제 동시 녹음 | 소음과 함께 약한 목소리 성분도 제거됨 |

소음이 없는 입력도 음소의 약한 성분을 깎을 수 있고, 전처리 뒤 조용한 환각이 생기면 기존
RMS·반복 가드가 잡지 못할 수 있다. 감쇠 상한을 조정해도 원본 STT를 넘지 못했으므로
`마이크 → denoise → STT` 경로를 만들지 않는다.

소음 평가는 Jetson 기준선 통과 후 수행한다. 실제 BRIO와 로봇 모터·팬·현장 소음을 동시에
녹음하고 quiet, SNR 10/5/0dB 또는 실측 조건별로 CER/WER, 숫자·부정어 보존, VAD 누락과
환각을 기록한다. 합성 소음만으로 현장 성능을 확정하지 않는다.

## 33.10 설계 변경과 미채택 이력

| 과거 검토안 | 현재 결정 | 이유 |
|---|---|---|
| Jetson Whisper small | 원격 Qwen3-ASR | 메모리 분리, L40S 정확도 우세 |
| faster-whisper large-v3/turbo | Qwen 유지 | 작은 지연 이득보다 핵심 표현 정확도 우선 |
| Jetson 로컬 3B LLM | GMS `gpt-5.4-mini` | 메모리·OOM·정확도 문제 |
| L40S Qwen3.5-4B LLM | GMS 유지 | 치명 오분류 1건, P95 열세 |
| 자유 대화형 LLM | 고정 질문+3필드 추출 | 예측 불가 발화와 의료 판단 방지 |
| 동적 TTS | 승인 사전 녹음 | 고정 질문, 검수 가능성, 지연·메모리 제거 |
| DeepFilterNet STT 전처리 | 원음 STT | 108조건과 실제 녹음에서 정확도 저하 |
| 공개 클라우드 Whisper API | 팀 GPU FastAPI | 무음 환각·보안·비용과 통제 범위 고려 |

과거 문서의 “STT·TTS 전부 Jetson 온디바이스” 또는 “배치 미확정” 문구는 폐기한다.
본 문서의 최종 구조가 현재 단일 기준이다.

## 33.11 장애 분류

| 증상 | 먼저 확인할 것 | 처리 |
|---|---|---|
| Jetson에서 연결 거부 | 서버 bind, 방화벽, 실제 IP·포트 | GPU 서버 health부터 복구 |
| health는 되지만 401 | 양쪽 API key 불일치 | `.env` 수정, 키 출력 금지 |
| 429 | 공유 GPU 동시성 포화 | 제한 재시도, 동시성 임의 증가 금지 |
| 503 | 모델 load·CUDA·VRAM | `nvidia-smi -i 3`, 서버 health 확인 |
| 마이크 무음 | ALSA 장치 번호·BRIO 입력 | 5초 직접 녹음부터 재검증 |
| 안내 음성이 응답으로 인식 | 스피커 방향·에코 가드 | 물리 배치와 청취 시작 시점 조정 |
| GMS 실패 | 호스트·키·timeout | STT 완료 건만 키워드 폴백 |
| 이동 반문이 UNKNOWN | transcript와 prompt 회귀 | 부정·반문 테스트 추가, 임의 키워드 YES 금지 |

## 33.12 남은 검증

- BRIO 실제 화자 3명 이상, 각 10발화 이상으로 현장 코퍼스를 만든다.
- quiet와 실제 로봇 소음에서 Qwen3-ASR CER/WER, 핵심 슬롯과 P50/P95를 측정한다.
- GPU 공유 부하 상태에서 429와 timeout 복구를 확인한다.
- Jetson 전체 스택의 RAM, CPU/GPU, 온도, 전력과 E2E 지연을 측정한다.
- Bluetooth 재연결과 사전 녹음 6개 청취·에코 검수를 완료한다.
- 실제 관제 전송 어댑터를 연결하고 보고 중복·누락을 확인한다.
- 사투리와 다국어는 별도 요구사항·코퍼스가 생긴 뒤 합격 범위를 확장한다.
