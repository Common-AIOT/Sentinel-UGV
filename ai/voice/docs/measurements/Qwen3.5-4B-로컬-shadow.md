# Qwen3.5-4B 로컬 정보 추출 shadow 결과

측정일: 2026-08-05

Jira: S15P11A301-270

결론: **운영 전환 보류, 기존 GMS `gpt-5.4-mini` 유지**

## 구성

- GPU: NVIDIA L40S 46GB, CUDA 12.8, 배정 장치 3만 사용
- 로컬 모델: `Qwen/Qwen3.5-4B`, BF16, non-thinking
- 서빙: FastAPI, Bearer 인증, localhost 기본 바인딩, 동시 실행 1개
- 출력: `lm-format-enforcer`로 3필드 JSON Schema 토큰 강제
- 런타임: PyTorch 2.11.0+cu128, Transformers 5.14.1
- 데이터: hard 8건 + 외부 독립 38건 = 46건
- 프롬프트: `sha256:09880e863955`
- 비교 조건: 두 모델 모두 같은 46케이스와 같은 현재 프롬프트로 1회 실행

현재 vLLM 0.26 휠은 CUDA 13 런타임을 요구해 CUDA 12.8 서버에서 로드되지
않았다. 모델이나 평가 조건을 바꾸지 않고 Transformers 직접 추론으로
전환했다. 선택 커널(FLA/causal-conv1d)이 없어 torch fallback 경로가 사용됐다.

## 결과

| 지표 | Qwen3.5-4B 로컬 | GMS gpt-5.4-mini |
|---|---:|---:|
| 요청 성공률 | 100.00% | 100.00% |
| Schema 유효율 | 100.00% | 100.00% |
| 슬롯 정확도 | 85.51% | 88.41% |
| 3필드 완전 일치 | 67.39% | 69.57% |
| 환각 슬롯 수 | 16 | 15 |
| 안전 치명 오분류 | **1** | **0** |
| P50 | 7,579.27ms | 1,054.17ms |

단일 반복이라 일관성 값 100%는 반복 재현성을 입증하지 않는다. 그러나
안전 치명 오분류 0건 기준을 이미 위반했으므로 추가 반복으로 승격하지 않았다.

## 치명 오분류와 차이

`child-speaker-mobility`에서 정답은 인원 미상, 이동 불가, 긴급 언급 미상이었다.
Qwen은 `1 / YES / YES`로 반환해 이동 불가를 이동 가능으로 뒤집었다.
같은 케이스에서 GMS도 완전 정답은 아니었지만 `null / UNKNOWN / YES`로 반환해
위험 상태를 안전 상태로 낮추는 치명 오류는 만들지 않았다.

## 판정

수용 기준 중 Schema 99% 이상은 통과했지만 다음 두 조건 때문에 불합격이다.

1. 안전 치명 오분류가 1건으로, 허용 기준 0건을 위반했다.
2. P50이 GMS보다 약 7.2배 느리고 슬롯·완전 일치 정확도도 낮다.

따라서 프로덕션 `sentinel_voice.llm`은 수정하지 않으며 GMS를 계속 기본으로
사용한다. 로컬 서버와 벤치마크 코드는 향후 프롬프트/커널/모델 개선 실험용
shadow 자산으로만 보존한다.

## 전환 및 롤백 원칙

향후 후보가 동일 데이터와 현장 발화에서 안전 치명 오류 0건, Schema 99% 이상,
GMS 이상 정확도와 허용 지연시간을 모두 만족할 때만 환경 변수 기반 shadow
토글을 추가한다. 먼저 응답을 보고에 사용하지 않는 5% shadow로 비교하고,
그 뒤 canary 순서로 올린다.

롤백은 토글을 GMS로 되돌리고 로컬 LLM 프로세스를 중지하는 것으로 끝나야 한다.
Jetson의 키워드 폴백과 기존 GMS 재시도/세션 게이트는 변경하지 않는다.

재현 명령과 요약 원본은 각각 `evaluation/local_llm_shadow.py`와
`results/local-llm-shadow-20260805/comparison-summary.json`에 있다.
