## 0. 이 테스트로 무엇을 확인하는가

다턴 대화 세션(`VoiceSessionRunner`)을 **사람이 직접 말해서** 검증한다.

| 확인 대상 | 판단 근거 |
|---|---|
| 5단계 대화 순서가 실제로 진행되는가 | INTRO→COUNT→MOBILITY→URGENT→CLOSING |
| 명세 33-3 **응답 4분류**가 올바르게 갈리는가 | 시나리오 A/C/D/E |
| 명세 33-6 **보고 9필드**가 옳은 값으로 채워지는가 | §5 기대 보고값 |
| 위험도 규칙(`voice-risk-v1.0`)이 재현되는가 | §5 판정표 |
| 안내 음성이 현장에서 들릴 수준인가 | 스피커 실청취 |

**범위 밖 (S15P11A301-159 완료 후 동작):** 비전 자동 트리거 · 관제 서버 실제 전송 ·
E-Stop 세션 중단 · 탐사 자동 재개. 이번 테스트에서 안 된다고 결함 처리하지 말 것.

## 3. 진행 방식 ⚠️ 읽고 시작할 것

**안내 음성이 끝나는 즉시 녹음이 시작된다.** 별도의 "말하세요" 신호는 없다.
콘솔에 `[PLAY] <질문>: ...` 줄이 뜨는 순간이 곧 녹음 시작 시점이다.
청취창은 **고정 길이**이므로 답을 마쳐도 시간이 끝날 때까지 기다린다.

| 질문 | 청취창 | 재질문 |
|---|---|---|
| INTRO | 5초 | **최대 1회** (무음일 때만) |
| COUNT | 6초 | 없음 |
| MOBILITY | 6초 | 없음 |
| URGENT | 8초 | 없음 |

- 전체 세션 **약 60~80초**. 내부 타임아웃은 **120초**이며 초과하면
  `terminationReason=TIMEOUT` + `riskLevel=UNKNOWN`으로 보고가 격하된다. 답을 길게 끌지 말 것.
- 로봇이 재생하는 문구는 **승인된 사전녹음 WAV 10개**뿐이다. 임의 TTS 생성은 없다.
- `SILENCE_RMS=0.005` 미달이면 무음 판정 → 스피커 볼륨과 마이크 거리(30~50cm) 유지.

### 실행 명령 (시나리오마다 로그 파일명 변경)

```bash
SENTINEL_DEVICE=cpu python -u -m sentinel_voice.pipeline 2>&1 | tee ~/voice_test_A.log
```

> `-u` 필수. 없으면 `tee` 버퍼링 때문에 멈춘 것처럼 보인다.

## 4. 시나리오 A~E 대본

### 시나리오 A — 표준 (중증) · 가장 먼저 실행

| # | 로봇이 재생하는 문구 (들리는 것) | 말할 대사 |
|---|---|---|
| 1 | 탐사 로봇입니다. 구조 요청을 돕겠습니다. 제 말이 들리면 대답해 주세요. | **"네, 들려요."** |
| 2 | 본인을 포함해서, 지금 여기 대화할 수 있는 분은 모두 몇 명인가요? | **"저랑 아저씨 한 분, 두 명이요."** |
| 3 | 지금 스스로 움직일 수 있나요? | **"다리가 눌려서 못 움직여요."** |
| 4 | 지금 어디가 가장 불편한가요? 숨쉬기 어렵거나 피가 많이 나면 말씀해 주세요. | **"숨쉬기가 좀 힘들어요."** |
| 5 | 구조 요청을 관제에 전달하고 있습니다. 잠시만 기다려 주세요. | (대답 없음, 종료) |

**합격:** `riskLevel=IMMEDIATE` · `urgentConditionReported=YES` · `reportedResponsiveCount=2`

### 시나리오 B — 경상 (자력 이동 가능) · A의 반대 극단

| # | 말할 대사 |
|---|---|
| 1 | **"네, 들립니다."** |
| 2 | **"저 혼자예요."** |
| 3 | **"네, 걸을 수 있어요."** |
| 4 | **"아니요, 괜찮습니다. 다친 데 없어요."** |

**합격:** `riskLevel=DELAYED` · `mobilityStatus=YES` · `urgentConditionReported=NO`

> 관전 포인트는 4번이다. 부정문("아니요")을 긴급 **없음**으로 옳게 뒤집는지 본다.
> `urgentConditionReported=YES`로 나오면 GMS 프롬프트의 부정 처리 문제다.

### 시나리오 C — 완전 무응답 (의식 없음 상정)

INTRO에서 **아무 말도 하지 않고 5초 대기** → `[NOVOICE]` 로그 후
"제 말이 들리면 다시 한번 대답해 주세요." 재생 → **다시 5초 침묵**.
이후 남은 질문에도 계속 침묵.

**합격:** `[NOVOICE]` 2회 + 재질문 WAV 재생 확인 + `anyResponseDetected=False` +
`riskLevel=IMMEDIATE`

> 이 시나리오에서 **COUNT/MOBILITY/URGENT를 끝까지 물어본다.** 정상 동작이다(§9-2).

### 시나리오 D — 발화는 있으나 STT 실패 ⭐ 명세 33-3 핵심

INTRO에서 **말이 아닌 소리**를 5초간 낸다. 신음("으으으…"), 웅얼거림, 숨 몰아쉬기.

**반드시 확인할 것**

- `[STTFAIL] INTRO: STT 무효 <사유>` 로그가 뜬다.
- **`anyResponseDetected`가 `False`가 아니라 `True`다.**

음성은 감지됐고 STT만 실패한 상황이므로 응답분류는 `VOICE_DETECTED_STT_FAILED`여야
하며, **무응답·의식없음으로 기록하는 것은 명세가 금지한다.** 여기서 `False`가
나오면 즉시 보고할 결함이다.

**합격:** `[STTFAIL]` 로그 + `anyResponseDetected=True` + `operatorReviewRequired=True`

### 시나리오 E — 모호한 답 (구조화 실패)

A와 동일하게 진행하되 **MOBILITY에서만** 다음과 같이 답한다.

> **"글쎄요… 잘 모르겠어요."**

응답분류는 `RESPONSE_UNRECOGNIZED`. 답은 했으나 값을 확정하지 못한 경우이며
`operatorReviewRequired=True`로 관제 확인 대상에 남는다.

**합격:** `mobilityStatus='UNKNOWN'` + 세션이 중단되지 않고 URGENT까지 진행

## 5. 관제 보고 형식 (33-6, 9필드 고정)

`safety.coerce_report()`가 강제하는 스키마다. **필드는 항상 이 9개**이며
자유서술·신체부위·개인식별 필드는 존재하지 않는다.

| 필드 | 타입 / 허용값 | 의미 |
|---|---|---|
| `responseScope` | `"GROUP"` **고정** | 마이크 1개라 개인에게 자동 귀속하지 않음 |
| `anyResponseDetected` | `true` / `false` / `null` | `null`은 관찰 자체를 못 한 경우(장치 오류) |
| `reportedResponsiveCount` | `int ≥1` / `null` | 본인 포함, **본인이 말한** 응답 가능 인원 |
| `reportedCountStatus` | `SELF_REPORTED_GROUP_COUNT` / `CONFIRMED_BY_OPERATOR` / `UNKNOWN` | 인원수 출처·확정 상태 |
| `countConfidence` | `0.0~1.0` / `null` | 측정값이 있을 때만 |
| `mobilityStatus` | `YES` / `NO` / `UNKNOWN` | 자력 이동 가능 여부 |
| `urgentConditionReported` | `YES` / `NO` / `UNKNOWN` | 호흡곤란·심한 출혈 등 언급 |
| `operatorReviewRequired` | `bool` | **현재 규칙상 항상 `true`** |
| `terminationReason` | `NORMAL` / `TIMEOUT` / `ABORTED_MANUAL` / `ABORTED_SAFETY` / `AUDIO_DEVICE_ERROR` / `GMS_UNAVAILABLE` / `UNKNOWN` | 세션 종료 사유 |

### 위험도 참고값 (별개 객체)

```python
{'riskLevel': ..., 'riskReasons': [...],
 'ruleVersion': 'voice-risk-v1.0', 'operatorReviewRequired': True}
```

판정 순서 — 위에서 먼저 걸리면 확정:

| 조건 | riskLevel |
|---|---|
| `terminationReason`이 NORMAL/UNKNOWN이 아님 | `UNKNOWN` |
| `anyResponseDetected == null` | `UNKNOWN` |
| `anyResponseDetected == false` | **`IMMEDIATE`** |
| `urgentConditionReported == YES` | **`IMMEDIATE`** |
| `mobilityStatus == NO` | `URGENT` |
| `mobilityStatus == YES` 이고 `urgentConditionReported == NO` | `DELAYED` |
| 그 외 | `UNKNOWN` |

> **LLM은 등급을 매기지 않는다.** GMS는 사실만 구조화하고 등급은 위 규칙표가
> 결정한다. 그래서 결과가 재현 가능하고 감사 가능하다.

## 6. 최종 콘솔 출력 (시나리오 A 전문)

```
▶ 트리거: VISION
모델 로딩... (device=cpu compute=int8 jetson=True stt=small llm=gpt-5.4-mini)
[PLAY] INTRO: 탐사 로봇입니다. 구조 요청을 돕겠습니다. 제 말이 들리면 대답해 주세요.
[STT] INTRO: 네, 들려요
[PLAY] COUNT: 본인을 포함해서, 지금 여기 대화할 수 있는 분은 모두 몇 명인가요?
[STT] COUNT: 저랑 아저씨 한 분, 두 명이요
[PLAY] MOBILITY: 지금 스스로 움직일 수 있나요?
[STT] MOBILITY: 다리가 눌려서 못 움직여요
[PLAY] URGENT: 지금 어디가 가장 불편한가요? 숨쉬기 어렵거나 피가 많이 나면 말씀해 주세요.
[STT] URGENT: 숨쉬기가 좀 힘들어요
[PLAY] CLOSING: 구조 요청을 관제에 전달하고 있습니다. 잠시만 기다려 주세요.
🩹 음성 세션 보고: {'responseScope': 'GROUP', 'anyResponseDetected': True, ...}
🚨 위험도 참고값: {'riskLevel': 'IMMEDIATE', 'riskReasons': ['긴급 상태가 있다고 발화함'], ...}
🧭 종료 상태: COMPLETED / 사유: NORMAL
📨 관제 보고 상태: PENDING (관제 전송 어댑터 미연결)
🔊 로봇: 구조 요청을 관제에 전달하고 있습니다. 잠시만 기다려 주세요.
⏱ E2E: 68.4s
```

마지막 세 줄이 종착점이다.

- `🩹` + `🚨` — **관제로 보낼 페이로드 전체.**
- `📨 PENDING (관제 전송 어댑터 미연결)` — **여기서 멈춘다. MQTT 발행이 없다.**
  `report_delivery.queue_report()`에 `enqueue` 콜백이 주입되지 않아 `PENDING`을
  반환한다. 콜백을 `sentinel_bridge`에 연결하는 것이 **S15P11A301-159** 범위다.
- 그래서 요구조자가 마지막에 듣는 문구는 **"전달하고 있습니다"(진행형)**이고,
  **"전달되었습니다"(완료형)는 나오지 않는다.** 관제 ACK를 받은 적이 없는데 완료를
  말하면 거짓이 되므로 `requires_report_success=True`로 재생 자체를 차단한다.
  ACK 연결은 **S15P11A301-116**.

### 로그 태그 사전

| 태그 | 의미 |
|---|---|
| `[PLAY]` | 안내 WAV 재생 완료 (이 줄 직후 녹음 시작) |
| `[STT]` | 유효 발화 인식 성공 |
| `[NOVOICE]` | 무음 또는 VAD 음성 미검출 |
| `[STTFAIL]` | 음성은 있었으나 STT 무효 (무응답으로 기록 **안 함**) |
| `[LLM]` | 추출 경로가 GMS가 **아닐** 때만 출력 (= 33-8 키워드 폴백) |
| `[WARN]` | 안내 음성 재생 실패 (자산 누락·형식 오류·장치 오류) |
| `[FAIL]` | 오디오 장치 오류 → `FAILED_AUDIO`로 세션 종료 |

## 9. 알려진 구조적 한계 (개선 예정, 결함 아님)

테스트하면 바로 눈에 띌 항목들이다. 미리 알고 보고, 결함으로 올리지 말 것.

1. **안내 문구가 두 번 들린다.** CLOSING이 `REPORT_PENDING` WAV를 쓰고, 직후
   `queue_and_announce()`도 `PENDING` 상태라 같은 WAV를 다시 재생한다.
2. **무응답인데도 남은 질문을 계속 한다** (시나리오 C). 상태머신이 INTRO 무응답 시
   조기 종료하지 않고 COUNT→MOBILITY→URGENT를 끝까지 재생한다. 현장에서는 의식 없는
   요구조자 앞에서 30초를 낭비하는 셈이다.
3. **질문 1개 = 필드 1개 고정.** "저 혼자고 다리 못 움직여요"라고 한 번에 말해도
   COUNT만 채우고 MOBILITY를 또 묻는다. 적응형 흐름은 **S15P11A301-148** 범위다.
4. **문구가 아직 구버전이다.** §4 표의 문구는 자연스러움 개편
   (S15P11A301-146~149) 전의 것이다. 어색하다는 피드백은 이미 인지된 사항이다.
5. **`operatorReviewRequired`는 항상 `true`.** `risk_assessment()`가 모든 분기에서
   `True`를 반환한다. 안전 기본값이며 결함이 아니다.

### 11-1. 실행 결과와 재시도

- 환경 점검: STT·VAD 모델 로드와 GMS 실호출을 포함해 전부 통과했다. 안내 WAV

  **조용한 환경 재시험 필요**로 남긴다. 재시험에도 같은 현상이 나면 Bluetooth
  재생 잔향 또는 주변 잡음의 VAD 오검출 여부를 원본 녹음 보존 기능과 함께
