# 음성 파이프라인 용어집

> 대상: AI 외 역할을 포함한 Sentinel UGV 팀 전체
> 범위: `ai/stt` 코드·문서·시험 결과에서 사용하는 용어
> 원칙: 일반적인 뜻보다 **이 프로젝트에서 사용하는 의미**를 우선 설명한다.

이 문서는 다른 문서에서 낯선 용어를 만났을 때 찾아보는 공통 사전이다. 의료 행위나
모델 성능을 과장하지 않도록, 비슷하지만 다른 개념도 함께 구분한다.

## 1. 전체 흐름과 구성요소

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **음성 세션** | 로봇이 안내를 시작한 뒤 요구조자의 답변을 듣고, 정보를 추출해 관제 보고를 만드는 한 번의 대화 단위다. |
| **파이프라인** | 입력이 여러 단계를 지나 최종 결과가 되는 전체 흐름이다. 여기서는 `VISION 트리거 → VAD → STT → GMS 정보 추출 → 위험도 참고 규칙 → 관제 보고 → 안내 음성`을 뜻한다. |
| **VISION 트리거** | 카메라·비전 모듈이 사람 또는 상호작용 대상을 발견해 음성 세션 시작을 요청하는 신호다. 음성 모듈이 항상 마이크를 듣고 있다는 뜻은 아니다. |
| **SED** | Sound Event Detection. 신음·충격음 같은 특정 소리 사건 감지 기능이다. 현재 주 트리거는 VISION이며, 과거 벤치의 `SED` 표시는 입력 출처 구분용으로 남아 있을 수 있다. |
| **VAD** | Voice Activity Detection. 오디오에서 사람의 말소리가 있는 구간을 찾는다. 말의 내용은 이해하지 않으며 STT에 넘길 구간을 정한다. |
| **STT** | Speech-to-Text. 음성을 글자로 바꾸는 기능이다. 현재 Jetson에서 `faster-whisper small`을 로컬 실행한다. |
| **LLM** | Large Language Model. 이 프로젝트에서는 발화에서 정해진 사실 3개를 추출하는 데만 사용하며 의료 판단이나 구조 순위를 맡기지 않는다. |
| **GMS** | SSAFY의 생성형 AI 모델 호출 서비스다. Jetson에 LLM을 설치하는 대신 GMS API로 `gpt-5.4-mini`를 호출한다. |
| **TTS** | Text-to-Speech. 글을 음성으로 합성하는 기능이다. 현재 운영 경로에는 TTS 모델을 탑재하지 않고 미리 승인한 WAV를 재생한다. |
| **사전녹음 안내 음성** | 문구와 음질을 미리 검수한 WAV 파일이다. 실행 중 LLM이 문구를 만들거나 TTS가 새 음성을 합성하지 않는다. |
| **상태머신** | 현재 상태와 입력에 따라 다음 상태를 명시적으로 결정하는 로직이다. 대화 단계, 종료 사유, 보고 전송과 탐사 재개 순서를 관리한다. |
| **다턴 대화** | 한 번 묻고 끝나는 것이 아니라 여러 질문과 답변이 이어지는 대화다. |
| **E2E** | End-to-End. 일부 함수가 아니라 트리거부터 관제 보고·안내까지 전체 경로를 연결해 시험한다는 뜻이다. |

## 2. 데이터와 관제 보고

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **전사문(transcript)** | STT가 음성을 글자로 변환한 결과다. 사람이 말한 원본 의도와 다를 수 있다. |
| **정보 추출** | 자유로운 문장에서 필요한 사실만 정해진 필드로 옮기는 작업이다. 현재 GMS는 `reportedResponsiveCount`, `mobilityStatus`, `urgentConditionReported`만 추출한다. |
| **응답 가능 총인원** | 화자 본인을 포함해 현재 음성으로 응답할 수 있다고 발화자가 직접 보고한 사람 수다. 동물과 응답 여부가 확인되지 않은 사람은 세지 않으며, 카메라 감지 인원과도 구분한다. |
| **구조화 데이터** | 사람이 읽는 문장 대신 프로그램이 필드명과 값으로 처리할 수 있게 정리한 데이터다. |
| **JSON** | `{ "필드명": 값 }` 형태의 데이터 표현 방식이다. 관제 보고와 GMS 응답에 사용한다. |
| **필드(field)** | JSON 안에서 하나의 의미를 담당하는 이름과 값의 쌍이다. 예: `mobilityStatus: "NO"`. |
| **슬롯(slot)** | 정보 추출 평가에서 정답 여부를 따로 세는 정보 칸이다. 현재 인원 수·이동 가능 여부·긴급 상태의 세 슬롯을 평가한다. |
| **스키마(schema)** | 어떤 필드가 있어야 하고 각 값의 자료형과 허용 범위가 무엇인지 정한 데이터 계약이다. |
| **파싱(parsing)** | 문자열로 받은 JSON 응답을 프로그램이 실제 데이터로 읽는 과정이다. GMS가 응답했어도 JSON 문법이 깨졌다면 실패한다. |
| **스키마 검증** | 파싱한 데이터가 필수 필드, 자료형, 허용값 규칙을 지키는지 검사한다. JSON 문법이 맞아도 계약을 어기면 실패한다. |
| **`null`** | 값이 아직 생성되지 않았거나 해당 단계가 실행되지 않아 값 자체가 없다는 뜻이다. |
| **`UNKNOWN`** | 관련 질문이나 처리는 수행했지만 답을 확정할 근거가 부족하다는 뜻이다. `null`과 동일하지 않다. |
| **자기보고(self-reported)** | 카메라나 의료진이 확인한 사실이 아니라 요구조자가 말로 알려준 내용이다. |
| **`riskLevel`** | 관제 검토를 돕는 위험도 참고값이다. 현재 `URGENT`, `ATTENTION`, `NORMAL`, `UNKNOWN`으로 표현한다. |
| **의료 triage** | 의료 전문가가 임상 관찰과 공식 기준으로 치료·이송 우선순위를 정하는 절차다. 현재 음성 정보만으로 수행할 수 없으며 `riskLevel`을 의료 triage나 최종 구조 순위라고 부르면 안 된다. |
| **관제 보고** | 음성 세션에서 확인한 사실, 처리 상태, 위험도 참고값을 관제 시스템에 전달하기 위한 구조화된 결과다. |
| **ACK** | Acknowledgement. 관제 측이 보고를 정상적으로 받았다는 확인이다. 보고 내용 동의나 구조 우선순위 확정은 아니다. |
| **Mission Manager** | 로봇 임무 흐름을 관리하는 상위 모듈의 계약상 명칭이다. 관제 ACK 이후 탐사 재개 여부를 결정한다. 실제 ROS 2 연동은 후속 대상이다. |
| **탐사 재개 승인** | 음성 모듈이 임의로 이동하지 않고 Mission Manager가 다음 탐사로 넘어가도 된다고 알리는 신호다. |

필드별 상세 의미와 예시는
[`음성-세션-보고-스키마.md`](음성-세션-보고-스키마.md)를 따른다.

## 3. 안전 처리와 장애 대응

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **환각(hallucination)** | 실제 입력에 없는 내용을 STT나 LLM이 있는 것처럼 생성하는 현상이다. |
| **환각 가드** | 무음·반복 문구·프롬프트 복사처럼 신뢰하기 어려운 STT 결과를 걸러내는 규칙이다. 모든 환각을 완전히 막는다는 뜻은 아니다. |
| **폴백(fallback)** | 주 처리 방식이 실패했을 때 더 제한적이고 안전한 대체 경로를 사용하는 것이다. |
| **33-8 키워드 폴백** | 통합 명세 33-8의 축소 정보 추출 경로다. STT는 끝났지만 GMS만 실패한 경우 제한된 키워드 규칙을 사용한다. GMS와 같은 자연어 이해 성능을 보장하지 않는다. |
| **세션 게이트** | 새 음성 세션 전에 GMS 호스트 연결 가능성을 검사해 시작 여부를 결정하는 경계다. |
| **호스트 도달성** | Jetson에서 GMS 서버 주소와 포트까지 네트워크 연결을 만들 수 있는지 여부다. 다른 인터넷 사이트 접속 성공과 같지 않다. |
| **TCP 연결 확인** | 실제 API 요청 전 GMS 호스트의 네트워크 포트까지 연결 가능한지 짧게 시험한다. 모델 정상 응답까지 보장하지는 않는다. |
| **타임아웃(timeout)** | 정해진 시간 안에 응답이 끝나지 않아 실패로 처리하는 것이다. |
| **재시도(retry)** | 일시 장애일 가능성이 있을 때 같은 요청을 제한된 횟수만큼 다시 보내는 것이다. |
| **401/403** | 인증 또는 권한 오류다. API 키·권한 문제일 가능성이 높아 자동 재시도로 해결되지 않는 것으로 분류한다. |
| **429** | 요청 과다 또는 할당량 제한이다. 일시적일 수 있어 정책에 따라 제한 재시도한다. |
| **5xx** | GMS 서버 측 오류 범위다. 일시 장애일 수 있어 제한 재시도한다. |
| **전송 대기** | 관제 보고를 즉시 전달하지 못해 유실하지 않고 후속 전송 주체에 넘기기 위해 대기하는 상태다. 실제 영속 큐·MQTT 연결은 백엔드 계약과 함께 완성해야 한다. |
| **안전 기본값** | 정보 부족 시 낙관적인 결론을 만들지 않고 `UNKNOWN`, 재질문, 관제 검토 필요처럼 보수적으로 처리하는 값이다. |

## 4. 모델 비교와 정량 평가

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **벤치마크(bench)** | 같은 데이터와 조건으로 후보 모델의 품질·속도·비용을 비교하는 시험이다. |
| **fixture** | 시험을 반복해도 같은 결과를 비교하도록 미리 고정한 입력과 기대값이다. |
| **정답 라벨(ground truth)** | 모델 결과를 채점하기 위해 사람이 미리 확정한 정답이다. |
| **요청 성공률** | GMS가 네트워크·서버 오류 없이 응답한 비율이다. 내용이 정답이거나 파싱 성공했다는 뜻은 아니다. |
| **파싱 성공률** | 응답을 JSON으로 읽고 요구 필드 구조까지 처리할 수 있었던 비율이다. 값이 정답이라는 뜻은 아니다. |
| **스키마 준수율** | 응답이 필드 수, 자료형, 허용값 등 출력 계약을 지킨 비율이다. |
| **슬롯 정확도** | 전체 정보 칸 중 정답과 정확히 일치한 칸의 비율이다. 한 문장의 세 슬롯을 각각 채점한다. |
| **완전 일치율** | 한 문장의 모든 슬롯이 동시에 정답인 비율이다. 하나만 틀려도 완전 일치가 아니다. |
| **출력 일관성** | 같은 입력의 반복 호출에서 같은 구조화 결과가 나오는 정도다. 같은 오답도 일관적일 수 있으므로 정확도와 함께 봐야 한다. |
| **환각 슬롯** | 입력 발화에 근거가 없는데 모델이 값을 만들어 낸 슬롯이다. |
| **정보 누락** | 입력에 명시된 정보를 추출하지 못하고 `UNKNOWN` 등으로 남긴 경우다. |
| **위험→안전 오판** | 실제보다 안전한 상태로 잘못 판정한 오류다. 현재 벤치에서는 이동 불가 `NO`를 가능 `YES`로 바꾸거나, 긴급 증상 있음 `YES`를 없음 `NO`로 바꾼 경우만 집계한다. |
| **회귀 검증** | 프롬프트나 코드 개선 후 기존에 맞던 사례가 새 변경으로 깨지지 않았는지 다시 확인하는 시험이다. |
| **스모크 테스트** | 실제 주요 경로가 최소 한 번 정상 동작하는지 빠르게 확인한다. 한 번의 성공으로 성능 분포를 증명하지 않는다. |
| **단위 테스트** | 외부 장비·GMS 없이 작은 함수나 규칙을 격리해 검증하는 자동 시험이다. |
| **통합 테스트** | 여러 모듈 또는 실제 장비·외부 API를 연결해 경계가 맞는지 확인하는 시험이다. |
| **P50** | 측정값의 중앙값이다. 요청 절반이 이 시간 이내에 끝났다는 뜻으로 해석한다. |
| **P95** | 요청 약 95%가 이 시간 이내에 끝나는 경계값이다. 느린 일부 요청을 반영해 운영 지연을 보는 데 사용한다. |
| **최대 지연** | 측정 중 가장 오래 걸린 한 건의 시간이다. 이상치 영향을 크게 받아 P95와 함께 본다. |
| **WER** | Word Error Rate. 정답과 STT 결과 사이의 단어 삽입·삭제·대체 오류 비율이다. 낮을수록 좋다. |
| **핵심 표현 보존율** | 인원 수, 이동 불가, 호흡 곤란처럼 후속 판단에 중요한 표현이 STT 결과에 남은 비율이다. |
| **발화 검출 재현율** | 실제 말한 구간 중 VAD가 음성으로 찾아낸 비율이다. |
| **RTF** | Real-Time Factor. `STT 처리 시간 ÷ 음성 길이`다. 1.0 이하면 10초 음성을 10초 이내에 처리한 것이다. |
| **베이스라인** | 변경 효과를 비교하기 위한 기존 기준 측정값이다. |

## 5. GMS 호출과 비용

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **API** | 프로그램끼리 정해진 요청·응답 형식으로 기능을 사용하는 접점이다. |
| **엔드포인트(endpoint)** | API 요청을 보내는 구체적인 서버 주소다. 공급자별 호환 주소가 다를 수 있다. |
| **API 키** | GMS 권한과 팀 크레딧에 연결된 비밀 인증값이다. `.env`에서만 관리하고 코드·로그·문서·커밋에 넣지 않는다. |
| **프롬프트(prompt)** | 모델에 역할, 추출 규칙, 출력 형식을 알려주는 지시문이다. |
| **프롬프트 버전** | 규칙 변경 전후를 구분하는 버전이다. 같은 모델도 프롬프트에 따라 정확도가 달라질 수 있다. |
| **프롬프트 해시** | 프롬프트 원문의 SHA-256 요약값이다. 시험 문구가 같은지 식별하며 원문을 복원하는 값은 아니다. |
| **토큰(token)** | 모델이 입력과 출력을 계산할 때 사용하는 텍스트 단위다. 글자·단어 수와 정확히 같지 않다. |
| **입력/출력 토큰** | 각각 모델에 보낸 내용과 모델이 생성한 응답에 사용된 토큰이다. |
| **추론 토큰** | 일부 모델이 최종 답 전 내부 추론에 사용했다고 보고하는 토큰이다. 화면의 JSON보다 총 토큰이 클 수 있는 이유다. |
| **usage** | API 응답의 입력·출력·총 토큰 사용량 정보다. 모델별 필드와 제공 범위가 다를 수 있다. |
| **GMS 크레딧** | GMS의 비용 단위다. 토큰 수와 같은 값이 아니며 모델별 입력·출력 단가가 적용된다. |
| **`reasoning_effort`** | GPT 계열 추론량 옵션이다. 현재 단순 추출에서는 `none`으로 불필요한 지연과 비용을 줄인다. |
| **`thinkingBudget`** | Gemini 계열 내부 사고 토큰 예산이다. 단순 추출 비교에서는 `0`을 사용했다. |
| **라이브 호출** | 모의 응답이 아닌 실제 GMS 서버 호출이다. 크레딧이 사용될 수 있어 벤치에서는 `--confirm-live`를 명시해야 한다. |

## 6. Jetson·메모리·실행 환경

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **Jetson Orin Nano** | 음성 파이프라인이 배포되는 NVIDIA 엣지 컴퓨터다. 팀 장비는 RAM 8GB 모델이다. |
| **엣지/온디바이스** | 외부 서버가 아니라 로봇의 Jetson에서 직접 처리한다는 뜻이다. 현재 VAD·STT는 온디바이스, LLM은 GMS 원격 호출이다. |
| **RAM** | 실행 중인 프로그램과 모델이 사용하는 주 메모리다. 저장장치 용량과 다르다. |
| **피크 RAM** | 측정 구간 중 RAM 사용량이 가장 높았던 값이다. 순간 OOM 위험 판단에 중요하다. |
| **Swap** | RAM 부족 시 저장장치 일부를 임시 메모리처럼 쓰는 영역이다. RAM보다 느리고 OOM 위험을 없애지는 않는다. |
| **OOM** | Out Of Memory. 필요한 메모리를 할당하지 못해 모델이나 프로세스가 종료되는 상태다. |
| **page cache** | 운영체제가 파일 읽기 속도를 위해 RAM에 보관하는 캐시다. 회수 가능한 영역이지만 메모리 분석에서 함께 확인한다. |
| **모델 가중치** | 학습된 모델의 실제 수치 데이터다. 코드와 별개로 최초 다운로드가 필요할 수 있다. |
| **사전 캐싱** | 배포 전 모델을 한 번 로드해 가중치를 저장장치에 받아 두는 절차다. 항상 RAM에 올려 둔다는 뜻은 아니다. |
| **상주 로드** | 프로세스 동작 중 모델을 RAM에 계속 유지하는 것이다. 디스크 캐싱과 구분한다. |
| **CPU/GPU** | CPU는 범용 연산 장치, GPU는 병렬 연산 장치다. 현재 Jetson STT는 패키지 제약으로 CPU 실행한다. |
| **CUDA** | NVIDIA GPU 연산 플랫폼이다. 설치돼 있어도 라이브러리가 CUDA 지원으로 빌드되지 않았다면 GPU 실행은 안 된다. |
| **CTranslate2** | `faster-whisper`의 실행 엔진이다. 현재 ARM64 패키지는 CUDA 지원이 없어 STT를 `cpu/int8`로 실행한다. |
| **int8 / float16** | 모델 계산의 숫자 정밀도다. 보통 int8이 메모리를 덜 쓰지만 환경에 따라 속도·정확도 차이가 있다. |
| **가상환경** | Python 패키지를 시스템과 분리하는 공간이다. PC는 Miniforge `sentinel-audio`, Jetson은 저장소 루트 `.venv`를 사용했다. |

## 7. 오디오 품질

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| **WAV / PCM** | WAV는 오디오 파일 형식, PCM은 소리를 숫자 샘플로 저장하는 방식이다. 안내 음성은 PCM WAV로 통일한다. |
| **sample rate** | 1초에 소리를 몇 번 측정했는지 나타낸다. STT 입력은 16kHz로 통일한다. |
| **mono** | 오디오 채널이 하나인 형식이다. 마이크 입력과 STT 처리는 mono로 통일한다. |
| **RMS** | 오디오의 평균적인 에너지·음량이다. 순간 최대값인 peak와 다르다. |
| **dBFS** | 디지털 최대 크기를 0dBFS로 둔 상대 음량 단위다. 일반 신호는 음수이며 0에 너무 가까우면 clipping 위험이 있다. |
| **peak** | 측정 구간에서 가장 큰 순간 진폭이다. |
| **clipping** | 신호가 표현 범위를 넘어 파형이 잘리고 소리가 왜곡되는 현상이다. |
| **SNR** | Signal-to-Noise Ratio. 음성과 배경 소음의 크기 비율이다. 낮을수록 소음 속 음성 인식이 어렵다. |
| **에코/재유입** | 스피커의 로봇 안내가 마이크에 다시 들어가 요구조자 발화로 처리되는 현상이다. |

## 8. 자주 혼동하는 차이

| 혼동하기 쉬운 표현 | 구분 |
|---|---|
| **GMS 응답 성공 vs 파싱 성공 vs 정답** | 서버 응답을 받았어도 JSON이 깨지면 파싱 실패이고, 파싱됐어도 값이 틀리면 오답이다. |
| **`null` vs `UNKNOWN`** | `null`은 값이 없거나 단계 미실행, `UNKNOWN`은 처리했지만 확정 불가다. |
| **슬롯 정확도 vs 완전 일치율** | 슬롯 정확도는 필드별 채점, 완전 일치율은 한 문장의 모든 필드가 맞아야 성공이다. |
| **누락 vs 환각 vs 위험→안전 오판** | 누락은 있던 정보를 못 찾은 경우, 환각은 없던 정보를 만든 경우, 위험→안전 오판은 실제 위험 정보를 반대로 안전하게 판정한 경우다. |
| **riskLevel vs 의료 triage** | riskLevel은 관제 참고용 규칙 결과, 의료 triage는 전문가의 공식 임상 분류다. |
| **가중치 캐싱 vs RAM 상주** | 캐싱은 저장장치에 미리 다운로드, 상주는 실행 중 RAM에 계속 올려 두는 것이다. |
| **토큰 vs GMS 크레딧** | 토큰은 처리량 단위, 크레딧은 모델별 단가가 반영된 비용 단위다. |
| **단위 테스트 vs 실제 장비 검증** | 단위 테스트는 코드 규칙 검증, BRIO 100·스피커·Jetson 실측은 별도 통합 검증이다. |
| **ACK vs 보고 승인** | ACK는 수신 확인일 뿐, 보고 검토나 구조 우선순위 결정 완료가 아니다. |

새 용어를 문서에 추가할 때는 이 용어집에도 같은 의미를 추가한다. 같은 개념에 여러
이름을 사용하지 않으며, 의료 판단으로 오해될 표현은
[`대화-안전-정책.md`](대화-안전-정책.md)의 제한을 우선 적용한다.
