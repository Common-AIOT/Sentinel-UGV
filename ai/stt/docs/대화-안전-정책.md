# 요구조자 대화·위험도·안내 정책

> Jira: S15P11A301-109
> 적용 범위: VISION 트리거 이후 음성 세션, GMS 정보 추출, 규칙 기반 triage, 관제 보고, 안내 음성

## 1. 결정 권한

- GMS는 요구조자의 발화에서 관찰 가능한 사실만 추출한다. 진단, 생존 가능성 판단,
  구조 순서 결정, 도착 시간 추정은 하지 않는다.
- `safety.triage_rule`의 결과는 관제가 빠르게 검토하기 위한 **위험도 참고값**이다.
- 최종 구조 우선순위와 현장 지시는 관제 담당자 또는 구조대원이 결정한다.
- 로봇은 참고값을 요구조자에게 직접 말하지 않는다. 특히 "당신은 적색 환자입니다",
  "가장 먼저 구조됩니다"처럼 확정적으로 안내하지 않는다.

## 2. 위험도 참고값

관제 전송 시 기존 색상 문자열만 보내지 않고, 다음 의미를 가진 필드로 전달한다.
구체적인 전송 스키마 정렬은 S15P11A301-113에서 수행한다.

```json
{
  "riskLevel": "IMMEDIATE",
  "riskReasons": ["의식 반응 없음", "언어 응답 불가"],
  "operatorReviewRequired": true
}
```

| `riskLevel` | 기존 표시 | 의미 | 대표 근거 |
|---|---|---|---|
| `IMMEDIATE` | 적색(즉시) | 즉시 확인이 필요한 참고값 | 무반응, 통증반응만 있음, 신음만 가능, 언어 응답 불가 |
| `URGENT` | 황색(응급) | 신속한 확인이 필요한 참고값 | 혼미, 이동 불가, 단어 수준 응답 |
| `DELAYED` | 녹색(경증) | 대화·이동이 가능하다고 관찰됨 | 의식 명료 및 이동 가능 |
| `UNKNOWN` | 미확인 | 정보 부족 또는 시스템 판정 불가 | 핵심 필드 미확인, 음성 품질 부족 |

정책:

- `operatorReviewRequired`는 항상 `true`다.
- `riskReasons`에는 실제 관찰값과 적용된 규칙만 기록한다.
- 시스템 장애, 마이크 오류, STT 실패, 네트워크 실패는 `IMMEDIATE`의 근거가 아니다.
- 정상적으로 질문을 재생하고 청취했는데 요구조자의 반응이 없을 때만
  `무응답 관찰`을 기록할 수 있다.
- 정보가 부족하면 등급을 추측하지 않고 `UNKNOWN`을 사용한다.

### 정식 의료 triage로 표현하지 않는 이유

현재 로봇의 음성 세션이 직접 수집하는 값은 음성 응답 여부, 자기보고 인원,
자력 이동 가능 여부와 긴급 상태 자기보고다. 이 정보만으로는 정식 의료
triage에 필요한 임상 관찰을 충족하지 못한다.

WHO의 Mass Casualty Interagency Integrated Triage Tool(MC-IITT)은 보행
가능 여부 외에도 기도 문제, 호흡 곤란, 대량 출혈 또는 관류 문제, 의식
변화 등을 평가하며 반복적인 재평가를 요구한다. 미국 HHS의 START
알고리즘도 자발 호흡, 호흡수, 관류, 명령 수행 능력 등을 함께 사용한다.
WHO MC-IITT FAQ는 대량환자 triage를 이상적으로 경험 있는 임상 인력이
수행해야 한다고 안내한다.

따라서 로봇은 다음 역할만 수행한다.

1. GMS와 규칙 파서가 발화에서 관찰 가능한 사실을 구조화한다.
2. 버전이 고정된 규칙 엔진이 `riskLevel`과 `riskReasons`를 계산한다.
3. 관제 화면은 영상·음성 원본, 구조화 리포트와 적용 규칙을 함께 표시한다.
4. 실제 구조 우선순위는 해당 정보를 검토한 관제 전문가 또는 구조대원이 결정한다.

`riskLevel`은 **관제의 우선 확인을 돕는 위험 신호 참고값**이다. 의료 진단,
정식 triage 등급 또는 최종 구조 순위를 의미하지 않는다. 로봇과 GMS는
`finalTriage`, `confirmedSeverity`, `medicalPriority` 같은 확정 표현을
생성하지 않는다.

참고 자료:

- [WHO Interagency Integrated Triage Tool](https://www.who.int/tools/triage)
- [WHO Mass Casualty IITT](https://cdn.who.int/media/docs/default-source/integrated-health-services-%28ihs%29/csy/mass-casualty---iitt-a0.pdf?sfvrsn=4e8859_1)
- [WHO MC-IITT FAQ](https://cdn.who.int/media/docs/default-source/integrated-health-services-%28ihs%29/csy/mc-iitt-faq.pdf?sfvrsn=3d3d71e9_1)
- [미국 HHS START Adult Triage Algorithm](https://chemm.hhs.gov/startalgotext.htm)

## 3. 무응답과 시스템 실패 구분

| 상황 | 기록 | 로봇 동작 |
|---|---|---|
| 질문 재생 성공, 마이크 정상, 청취 구간에 음성 없음 | `NO_RESPONSE_OBSERVED` | 1회 재질문 후 관제에 무응답 관찰 보고 |
| 음성은 있으나 STT 신뢰도 부족 | `STT_UNCERTAIN` | 1회 재질문, 계속 실패하면 정보 부족 보고 |
| 마이크 열기 또는 녹음 실패 | `AUDIO_DEVICE_ERROR` | 무응답으로 분류하지 않고 시스템 장애 보고 |
| 세션 시작 전 GMS 단절 확인 | `GMS_UNAVAILABLE_PRE_SESSION` | 신규 STT 대화 없이 안전 안내 및 전송 대기 |
| STT 완료 후 GMS 실패 | `GMS_UNAVAILABLE_POST_STT` | 제한 재시도 후 33-8 축소 보고 |

무응답 관찰만으로 의학적 상태를 확정하지 않는다. 다만 관제 검토가 필요한 높은 위험
신호로 전달할 수 있으며, 최종 우선순위는 관제가 결정한다.

## 4. 구조 ETA 정책

### 허용

- 관제 서버가 제공한 `etaMinutes`와 `etaUpdatedAt`만 사용한다.
- ETA가 유효할 때도 확정 표현 대신 범위와 변동 가능성을 알린다.
- 오래된 ETA는 재사용하지 않는다. 유효 시간은 관제 계약에서 확정하며, 확정 전에는
  `etaUpdatedAt`이 없는 값을 사용하지 않는다.

예시:

```text
구조대가 약 15분 후 도착할 예정입니다. 현장 상황에 따라 달라질 수 있습니다.
```

### 금지

- GMS 또는 로봇이 이동 거리만 보고 ETA를 생성하거나 보정하는 행위
- 관제 승인값이 없는데 임의의 시간을 안내하는 행위
- "정확히 10분 뒤 도착합니다"와 같은 확정 표현
- 오래된 ETA를 네트워크 복구 후 그대로 재생하는 행위

ETA가 없을 때는 다음 고정 문구를 사용한다.

```text
구조 요청을 관제에 전달하고 있습니다. 현재 위치에서 안전하게 기다려 주세요.
```

## 5. 안내 음성 정책

안전 필수 문구는 사전녹음 WAV를 사용한다. 자유 생성 문장은 사용하지 않는다.
동적 ETA 안내는 관제 값과 승인된 템플릿을 결합하는 기능이 마련되기 전까지 재생하지 않는다.

| 이벤트 | 안내 문구 | 재생 방식 |
|---|---|---|
| 최초 질문 | 탐사 로봇입니다. 구조 요청을 돕겠습니다. 제 말이 들리면 대답해 주세요. | 사전녹음 |
| 응답 인원 질문 | 지금 주변에 대화할 수 있는 분이 모두 몇 명인가요? | 사전녹음 |
| 이동 가능 여부 | 지금 스스로 움직일 수 있나요? | 사전녹음 |
| 상태·긴급 징후 질문 | 지금 어디가 가장 불편한가요? 숨쉬기 어렵거나 피가 많이 나면 말씀해 주세요. | 사전녹음 |
| 무응답 재질문 | 제 말이 들리면 다시 한번 대답해 주세요. | 사전녹음 |
| STT 불명확 | 목소리가 잘 들리지 않았습니다. 천천히 다시 말씀해 주세요. | 사전녹음 |
| 관제 보고 대기 | 구조 요청을 관제에 전달하고 있습니다. 잠시만 기다려 주세요. | 사전녹음 |
| 관제 보고 완료 | 구조 요청이 관제에 전달되었습니다. | 사전녹음 |
| 보고 완료·탐사 재개 | 구조 요청이 관제에 전달되었습니다. 다른 구역을 확인하기 위해 탐사를 계속하겠습니다. | 사전녹음 |
| 네트워크 단절 | 통신 연결을 확인하고 있습니다. 연결되는 대로 구조 요청을 전달하겠습니다. | 사전녹음 |
| ETA 있음 | 구조대가 약 `{etaMinutes}`분 후 도착할 예정입니다. 현장 상황에 따라 달라질 수 있습니다. | 승인 템플릿 기반 동적 음성, 후속 구현 |
| ETA 없음 | 구조 요청을 관제에 전달하고 있습니다. 현재 위치에서 안전하게 기다려 주세요. | 사전녹음 |

실제 파일명, 안정적인 이벤트 코드와 WAV 규격은
[`사전녹음-안내-음성.md`](사전녹음-안내-음성.md)를 단일 기준으로 사용한다.

문구 작성 원칙:

- 짧고 한 번에 한 가지 행동만 요청한다.
- 공포를 유발하거나 구조 순서를 확정하는 표현을 사용하지 않는다.
- 관제 전송이 실제로 성공한 뒤에만 "전달했습니다"라고 말한다.
- 전송 대기 상태에서는 "전달하고 있습니다"라고 구분한다.
- 이동을 권하기 전에 현장 안전과 관제 지시를 우선한다.
- 상대 좌표만으로 요구조자의 명확한 위치가 전달됐다고 안내하지 않는다.
- 탐사 재개 안내는 관제 전송 성공과 Mission Manager의 재개 승인이 모두 확인된 경우에만 재생한다.
- 음성 안내 재생 완료 후 주행 안전 확인을 거쳐 탐사를 재개한다.

## 7. 완료 조건

- 위험도는 참고값이며 최종 결정권자가 관제임을 모든 관련 문서가 동일하게 표현한다.
- ETA는 관제 승인값이 있을 때만 안내한다.
- 무응답과 장치·STT·네트워크 실패가 별도 상태로 정의된다.
- 사전녹음 대상 문구와 동적 안내 대상이 구분된다.
- 후속 구현 Jira가 본 정책을 참조한다.
