# 33. 피해자 음성 상호작용 설계 [확정]

## 33.1 한 줄 결론

현재 운영 구조는 **Jetson 로컬 VAD → L40S FastAPI Qwen3-ASR → GMS
`gpt-5.4-mini` 구조화 → 규칙 기반 위험도 → 승인된 사전 녹음 WAV 재생**이다.

```mermaid
flowchart LR
    encounter["VISION Encounter"] --> guide["사전 녹음 안내"]
    guide --> mic["BRIO 100 마이크"]
    mic --> vad["Jetson Silero VAD"]
    vad --> asr["L40S FastAPI\nQwen3-ASR-1.7B"]
    asr --> guard["환각·빈 전사 가드"]
    guard --> gms["GMS gpt-5.4-mini\n3필드+추가 요구조자 제보 구조화"]
    gms --> rule["규칙 기반 위험도"]
    rule --> report["관제 보고 인계"]
    report --> closing["종료 안내 후 탐사 재개"]
```

| 단계 | 최종 선택 | 배치 |
|---|---|---|
| 입력 | BRIO 100 내장 마이크 | Jetson |
| 안내 | 승인된 사전 녹음 WAV 6개 | Jetson |
| VAD | Silero VAD | Jetson |
| STT | `Qwen/Qwen3-ASR-1.7B` | L40S Device3 FastAPI |
| 정보 추출 | GMS `gpt-5.4-mini` | 외부 API |
| LLM 장애 폴백 | 제한된 키워드 파서 | Jetson |
| 위험도 | `voice-risk-v1.1` 명시 규칙 | Jetson |
| 출력 | 블루투스 A2DP 스피커 | Jetson |

동적 TTS, Jetson 로컬 Whisper, Jetson 로컬 LLM은 운영 경로가 아니다. DeepFilterNet은
관제 청취본 후처리용이며 STT 입력 앞에 연결하지 않는다.

## 33.2 안전 경계

- LLM은 의료 진단, 구조 우선순위 확정, 주행 명령을 하지 않는다.
- LLM은 인원 수, 이동 가능 여부, 긴급 상태, 추가 요구조자 제보(`additionalPersonReports`)만 정해진 JSON으로 추출한다.
- 위험도는 추출값을 입력으로 하는 명시적 규칙이며 관제 검토용 참고값이다.
- 로봇은 요구조자에게 위험 등급을 말하지 않는다.
- STT 실패를 무응답으로 기록하지 않는다.
- **순간 유실을 대화 종결로 기록하지 않는다**(S15P11A301-332). 유실 신호가 오면
  `LOST_GRACE`로 들어가 재감지를 기다리고, 재감지되면 대화를 잇는다. 유예 창의
  주인은 `mission_manager`다 — 창이 닫히면 임무 상태가 `INTERACTING`·
  `POST_RECORDING`을 벗어나므로 그것을 신호로 쓴다. **창 길이를 음성 쪽에
  복사하지 않는다.** 값을 복사해 두 노드의 관용도가 어긋난 것이 이 결함의
  원인이었다 — 2026-08-07 리허설에서 유실 구간이 **0.179초**였는데
  `mission_manager`는 재감지로 회복했고 음성은 종결했다. 답까지 받아놓고
  (`[STT] 나 보여?`) 버렸다. 통합 부하의 탐지가 8.4 FPS이므로 프레임 두어 장이면
  0.2초다.
- 네트워크가 끊긴 상태에서는 신규 음성 세션을 시작하지 않는다.
- **알려진 결함:** ROS 경로는 GMS gate 차단 시 `guide_code=None`을 안내 자산 키로 사용해 예외가 나고, 의도한 `GMS_UNAVAILABLE`이 아니라 `AUDIO_DEVICE_ERROR`/`FAILED_AUDIO`로 보고된다. 단독 파이프라인은 이 가드를 처리한다.
- 이미 STT가 끝난 뒤 GMS만 실패한 경우에만 키워드 폴백으로 축소 보고한다.
- 원음, API 키와 인증 헤더를 일반 애플리케이션 로그에 남기지 않는다.

## 33.3 대화 상태 머신

질문은 부상 우선 순서로 한 번씩 진행한다.

| 단계 | 파일 | 승인 안내 문구 |
|---|---|---|
| `INTRO` | `guide_intro.wav` | 구조 로봇입니다. 들리면 대답해 주세요. |
| `URGENT` | `guide_ask_urgent.wav` | 다친 곳이 있으십니까? |
| `MOBILITY` | `guide_ask_mobility.wav` | 움직일 수 있습니까? |
| `COUNT` | `guide_ask_count.wav` | 주변에 다른 인원이 있습니까? |
| `RETRY_NO_RESPONSE` | `guide_retry_no_response.wav` | 제 말이 들린다면 대답해주십시오. |
| `REPORT_SUCCEEDED_DEPARTURE` | `guide_report_succeeded_departure.wav` | 구조 요청이 전달되었습니다. 다시 탐색을 시작합니다. |

INTRO에서 무응답이면 한 번만 재질문한다. 이후 값이 확정되지 않아도 같은 질문을 반복하지
않고 `UNKNOWN`으로 진행해 대화를 끝낸다.

### 턴 결과 4분류

| 상태 | 음성 감지 | STT | 구조화 | 의미 |
|---|---:|---:|---:|---|
| `NO_VOICE_DETECTED` | 아니오 | — | — | 실제 무응답 |
| `VOICE_DETECTED_STT_FAILED` | 예 | 실패 | — | 사람은 답했지만 전사 실패 |
| `RESPONSE_UNRECOGNIZED` | 예 | 성공 | 실패 | 문장은 있으나 필드 확정 불가 |
| `ANSWER_STRUCTURED` | 예 | 성공 | 성공 | 필드 기록 가능 |

반문과 맥락을 고려한다. 예를 들어 “다리 다쳤는데 움직일 수 있겠냐고요”는 질문 맥락상
이동 불가를 뜻하므로 `mobilityStatus=NO`다. 단순 키워드 `움직일 수`만 보고 `YES`로
판정하지 않는다.

## 33.4 보고 계약

세션 보고의 기준 필드는 다음과 같다.

```json
{
  "responseScope": "GROUP",
  "anyResponseDetected": true,
  "reportedResponsiveCount": 2,
  "reportedCountStatus": "SELF_REPORTED_GROUP_COUNT",
  "countConfidence": null,
  "mobilityStatus": "NO",
  "urgentConditionReported": "YES",
  "operatorReviewRequired": true,
  "terminationReason": "NORMAL"
}
```

| 필드 | 책임 주체 |
|---|---|
| `anyResponseDetected` | VAD·상태 머신 |
| `reportedResponsiveCount` | GMS 또는 키워드 추출 결과 |
| `mobilityStatus` | GMS 또는 키워드 추출 결과 |
| `urgentConditionReported` | GMS 또는 키워드 추출 결과 |
| `terminationReason` | 상태 머신 |
| `riskLevel`, `riskReasons` | 규칙 엔진 |
| 최종 구조 판단 | 관제자 |

`UNKNOWN`은 질문했지만 값이 확정되지 않았다는 뜻이다. `null`은 해당 필드에 값 자체가
적용되지 않거나 제공되지 않았다는 뜻이다. 여러 사람이 있는 경우 자동 화자 분리를 하지
않고 `responseScope=GROUP`으로 전달한다.

음성 보고에는 상호작용 당시 로봇 위치와 COUNT 답변에 이미 포함된 추가 요구조자
제보도 함께 전달한다.

```json
{
  "encounterPose": {
    "x": 12.4,
    "y": 7.8,
    "yaw": 1.57,
    "mapId": "floor-1"
  },
  "additionalPersonReports": [
    {
      "subjectText": "우리 아기",
      "reportedCount": 1,
      "countStatus": "EXACT",
      "locationText": "2층",
      "reportedFloor": 2,
      "groundingStatus": "UNGROUNDED",
      "responseStatus": "UNKNOWN",
      "certaintyStatus": "ASSERTED",
      "rawUtterance": "2층에 우리 아기가 있어요",
      "verificationStatus": "UNVERIFIED",
      "operatorReviewRequired": true
    }
  ]
}
```

`encounterPose`는 요구조자의 정밀 좌표가 아니라 음성 상호작용이 발생한 로봇 위치다.
`additionalPersonReports.reportedCount`는 화자를 제외한 추가 사람 수이며
`reportedResponsiveCount`와 합치지 않는다. 존재만 제보된 사람의 응답 상태는
`UNKNOWN`이다. 위치 문자열은 STT 원문에 실제로 있는 조각만 허용하며 모든 제보는
`UNVERIFIED`로 전달한다. “저기 계단 옆에 있어요”처럼 숫자가 생략된 제보는
`reportedCount=null`, `countStatus=PRESENCE_CONFIRMED_COUNT_UNKNOWN`으로 남겨
임의로 한 명이라고 추정하지 않는다. SLAM 점유 지도에는 “계단” 같은 의미 정보가 없으므로
`groundingStatus=UNGROUNDED`이며 관제 화면의 텍스트 단서로만 표시한다. 별도 위치 질문,
좌표 추정, 지도 핀, 자동 목표지 생성과 층간 이동은 수행하지 않는다.

관제 ACK를 기다리는 구조는 사용하지 않는다. 보고는 전송 어댑터의 성공·대기 상태로 인계하고,
종료 안내는 한 번만 재생한 뒤 Mission Manager 계약에 따라 탐사를 재개한다.

## 33.5 GPU ASR 서버

### API 계약

```http
GET /health
POST /v1/asr
Authorization: Bearer <ASR_API_KEY>
Content-Type: multipart/form-data
```

지원 입력은 WAV/FLAC/OGG, mono/stereo, 8~48kHz이며 기본 제한은 30초·16MiB다. 공유
GPU 동시 추론 기본값은 1건이다.

| HTTP | 오류 코드 | 클라이언트 처리 |
|---:|---|---|
| 401 | `UNAUTHORIZED` | 키·환경 설정 확인, 재시도 안 함 |
| 413 | `AUDIO_TOO_LARGE`, `AUDIO_TOO_LONG` | 입력 계약 수정 |
| 415 | `UNSUPPORTED_AUDIO_TYPE`, `INVALID_AUDIO` | 녹음·인코딩 확인 |
| 422 | `UNSUPPORTED_LANGUAGE`, `UNSUPPORTED_SAMPLE_RATE` | 요청 계약 수정 |
| 429 | `ASR_OVERLOADED` | 제한 재시도 후 STT 실패 기록 |
| 503 | `MODEL_NOT_READY`, `MODEL_INFERENCE_FAILED` | health 확인 후 제한 재시도 |

오류 응답은 `error.code`, `message`, `request_id`, `retryable`을 포함한다. Jetson은 어떤
서버 오류도 `NO_VOICE_DETECTED`로 바꾸지 않는다.

### L40S 실행

```bash
cd /path/to/S15P11A301/ai/voice
python3.12 -m venv .venv-gpu-asr
source .venv-gpu-asr/bin/activate
python -m pip install -U pip
python -m pip install -r asr_server/requirements.txt

cp asr_server/.env.example .env.gpu-asr
set -a
source .env.gpu-asr
set +a
python -m asr_server
```

`ASR_CUDA_VISIBLE_DEVICES=3`은 프로세스 내부 `cuda:0`을 물리 Device3에 연결한다.

```bash
nvidia-smi -i 3
curl -sS http://127.0.0.1:18100/health
```

기본 바인딩은 `127.0.0.1:18100`이다. Jetson이 직접 접근하는 격리 개발망 시험에서만
`0.0.0.0`과 평문 HTTP 예외를 사용한다. 장기 운영은 TLS reverse proxy, VPN 또는 승인된
SSH 터널 뒤에 둔다. 포트를 인터넷에 직접 공개하지 않는다.

### 보안

- Bearer 또는 `X-API-Key` 인증을 필수로 한다.
- `.env.gpu-asr`와 실제 키는 Git에 넣지 않는다.
- 업로드 임시 파일은 성공·실패와 무관하게 요청 종료 시 삭제한다.
- 원음과 전사문을 ASR 서버 로그에 남기지 않는다.
- 타 팀이 공유 GPU를 사용 중이면 프로세스를 임의로 종료하지 않는다.

#### PulseAudio 기본 소스가 BRIO여야 한다

**장치 목록에 BRIO가 보이는 것으로는 부족하다.** 확인할 것은 기본 소스다.

```bash
pactl info | grep 'Default Source'
# alsa_input.usb-046d_Brio_100_...   ← 정상
# alsa_input.platform-sound.analog-stereo   ← 젯슨 온보드 입력. 아무것도 꽂혀 있지 않다
```

기본 소스가 온보드 아날로그 입력으로 잡히면 **디지털 무음**(`peak=0.0`)이 나온다. 2026-08-07
E2E 리허설이 그 상태였고 대가가 둘이었다(S15P11A301-330).

| 소비자 | 증상 |
| --- | --- |
| 음성 인식 | 요구조자가 대답했는데 무응답으로 판정하고 세션이 즉시 종료 |
| 증빙 영상 오디오 | 이벤트 MP4의 오디오 트랙이 `mean_volume -91.0 dB`(완전 무음) |

두 소비자가 **같은 기본 소스**를 쓴다 — 음성의 PortAudio 경로와 `stream_pipeline`의
`pulsesrc`다. 증빙 오디오는 명세 32-6 요구사항이므로 무음이면 요구조자와의 대화가 남지
않는다. **파일은 정상 생성되고 오디오 트랙도 있어서 겉으로는 성공처럼 보인다.**

`scripts/demo_up.sh`가 기동 시 BRIO를 기본 소스로 지정하고 `PULSE_SOURCE`를 export한다
(스택의 단일 진입점이자 모든 노드의 부모다). 그래서 **그 스크립트로 올린 스택은 이 문제가
없다.** 손으로 `ros2 launch`를 부르거나 노드를 개별 실행할 때는 직접 확인한다.

무음이 잡히면 `session_runner`가 `[FAIL] ... 입력이 디지털 무음이다`와 함께 확인 절차를
로그에 남긴다. 무응답과 장치 오류를 구별하는 판정은 S15P11A301-257이 넣었다.

## 33.9 소음과 잡음 제거

DeepFilterNet은 **관제자가 듣는 녹음 후처리에는 채택**, **STT 전처리에는 미채택**한다.

| 관측 | 결과 |
|---|---|
| 합성 A/B 108조건 | 원본 승 58, denoise 승 16, 무승부 34 |
| CER 중앙값 | 원본 0.467, denoise 0.667 |
| 처리 비용 | 60초 음성 약 1초, RTF 0.017 수준 |
| 실제 동시 녹음 | 소음과 함께 약한 목소리 성분도 제거됨 |

소음이 없는 입력도 음소의 약한 성분을 깎을 수 있고, 전처리 뒤 조용한 환각이 생기면 기존
RMS·반복 가드가 잡지 못할 수 있다. 감쇠 상한을 조정해도 원본 STT를 넘지 못했으므로
`마이크 → denoise → STT` 경로를 만들지 않는다.

실제 육성과 수집 소음의 디지털 합성 평가는 수행했으며, 다음 단계는 BRIO와 로봇
모터·팬·현장 소음을 동시에 녹음하는 것이다. quiet, SNR 10/5/0dB 또는 실측 조건별로
CER/WER, 숫자·부정어 보존, VAD 누락과 환각을 기록한다. 디지털 합성만으로 현장 성능을
확정하지 않는다.

### S15P11A301-303 실제 육성·수집 소음 진단 기준선

직접 녹음한 한국어 도메인 발화 16개와 수집한 소음 6종(`fireburn`, `moto`, `motor`,
`realmotor`, `realsounds`, `siren`)을 사용했다. 원본은 수정하지 않고 외부 작업 폴더에서
각 발화에 SNR 10/5/0dB로 디지털 합성했다. clean 16건, 소음 혼합 288건, 소음 전용
6건으로 총 310조건이다. ASR 입력은 실제 Voice 파이프라인과 같은 16kHz mono 및 RMS
정규화를 적용했다.

이는 실제 사람 목소리와 실제 녹음 소음을 이용한 통제 실험이지만, 마이크 앞에서 동시에
녹음한 현장 실험은 아니다. 공간 잔향, BRIO 방향성, 로봇 진동과 부상자의 약한 발성은
재현하지 못하며 화자도 1명뿐이다.

기존 로컬 실측 세션도 원본을 수정하지 않고 재분석했다. 기존 RMS 선게이트 0.005 아래의
세 파일을 정규화 후 Silero와 로컬 Whisper small로 교차 확인한 결과는 다음과 같다.

| 원본 RMS | Silero | Whisper small | 기존 판정 |
|---:|---|---|---|
| 0.000311 | 음성 감지 | 빈 전사 | 무음 |
| 0.002998 | 음성 감지 | `네` | 무음 |
| 0.004041 | 음성 감지 | `없습니다` | 무음 |

기존 0.005는 약한 실제 발화 두 건을 VAD 전에 제거했다. 세 파일을 분리하면서 약한 발화를
VAD까지 보내도록 `SENTINEL_SILENCE_RMS` 기본값을 **0.001**로 낮췄다. 디지털 무음
장치 오류 판정(`SILENT_INPUT_PEAK=1e-6`)은 그대로 유지하며, 0.001 이상 입력도 Silero가
음성이 아니라고 판단하면 STT로 보내지 않는다.

이 벤치의 Silero 설정(`config.VAD_OPTS` — `threshold=0.5`,
`min_speech_duration_ms=150`, `min_silence_duration_ms=500`, `speech_pad_ms=300`)은
음성 304/304를 감지해 발화 누락은 없었다. 소음 전용은 3/6(`motor`, `realmotor`,
`realsounds`)을 음성으로 오탐했다. 다만 이 6건을 Qwen에 직접 입력했을 때 전사는 모두
빈 문자열이어서 ASR 환각은 0/6이었다. VAD는 제거하지 않되, 비음성 오탐률은 후속 현장
실험에서 측정한다.

> **알려진 불일치 — 이 수치는 운영 경로 설정이 아니다.** `VAD_OPTS`를 실제로 넘기는
> 곳은 `evaluation/vad_noise_bench.py` 하나뿐이다. 운영 경로인
> `sentinel_voice.pipeline.has_speech()`와 `evaluation/pipeline_bench.py`는
> `get_speech_timestamps`에 옵션을 넘기지 않으므로 **silero-vad 라이브러리 기본값**
> (`min_speech_duration_ms=250`, `min_silence_duration_ms=100`, `speech_pad_ms=30`)
> 으로 동작한다. `threshold=0.5`만 기본값과 우연히 같다.
>
> 따라서 위 304/304는 튜닝 설정 기준값이며 운영 경로의 발화 누락률로 재사용하면
> 안 된다. 특히 `SENTINEL_SILENCE_RMS`를 0.001로 낮춰 약한 발화를 VAD까지 보내도
> 운영 Silero의 최소 발화 길이가 250ms이므로 아주 짧은 응답(`네`)은 여전히
> 누락될 수 있다. 정합 방법은 두 가지이며 실기 재검증 없이 코드를 바꾸지 않는다.
>
> 1. `has_speech()`에 `**config.VAD_OPTS`를 넘겨 운영을 튜닝값에 맞춘 뒤 Jetson에서 재측정
> 2. 튜닝값을 폐기하고 라이브러리 기본값 기준으로 벤치를 다시 돌림
>
> 현재는 **미해결 상태로 기록만 한다**(프로젝트 종료 시점 실기 접근 불가).

L40S Device3의 Qwen3-ASR-1.7B 결과는 다음과 같다.

| 조건 | 요청 | micro CER | micro WER | 핵심어 보존 |
|---|---:|---:|---:|---:|
| clean | 16/16 | 17.74% | 32.00% | 20/30 (66.67%) |
| SNR 10dB, 6소음 통합 | 96/96 | 30.11% | 47.33% | 115/180 (63.89%) |
| SNR 5dB, 6소음 통합 | 96/96 | 36.69% | 54.00% | 108/180 (60.00%) |
| SNR 0dB, 6소음 통합 | 96/96 | 45.03% | 62.67% | 98/180 (54.44%) |
| 전체(소음 전용 포함) | **310/310** | **36.25%** | **53.47%** | **341/570 (59.82%)** |

소음 종류별 micro CER를 분리하면 다음과 같다. 각 칸은 동일한 실제 육성 16개를 해당
소음과 SNR로 합성한 결과다.

| 소음 | 10dB CER | 5dB CER | 0dB CER | 판정 |
|---|---:|---:|---:|---|
| `siren` | 18.55% | 18.55% | 18.55% | 가장 안정적 |
| `fireburn` | 17.74% | 20.16% | 21.77% | 비교적 양호 |
| `motor` | 19.35% | 22.58% | 22.58% | 비교적 양호 |
| `realsounds` | 20.97% | 20.16% | 26.61% | 0dB에서 일부 악화 |
| `moto` | 33.06% | 44.35% | 75.00% | 취약 |
| `realmotor` | 70.97% | 94.35% | 105.65% | 매우 취약 |

clean CER 17.74%와 비교하면 `siren`, `fireburn`, `motor`의 추가 악화는 제한적이고,
`realsounds`는 0dB에서 일부 악화됐다. 반면 `moto`와 `realmotor`는 SNR이 낮아질수록
전사가 크게 훼손됐다. CER는 정답보다 긴 환각성 삽입도 편집 오류로 계산하므로 100%를
넘을 수 있으며, `realmotor@0dB`의 105.65%는 측정 오류가 아니다. 모든 모터 소음에
동일하게 약한 것은 아니고 수집된 `motor.wav`와 `realmotor.wav`의 결과도 뚜렷하게
달랐으므로, 발표에서는 “특정 오토바이·실제 모터 소음에 취약했다”고 범위를 한정한다.

전체 지연은 P50 259.57ms, P95 408.31ms, inference P50/P95는 170.42/319.16ms,
평균 RTF는 0.0342였다. 위험 발화를 안전으로 뒤집은 경우는 0건이었다. 정확도 최악 조건은
`realmotor@0dB`(CER 105.65%), `realmotor@5dB`(94.35%), `moto@0dB`(75.00%)였다.

따라서 원격 Qwen은 지연과 위험 극성 보존을 근거로 잠정 유지하지만, 현재 코퍼스는
quiet/SNR 목표 CER를 통과하지 못했다. “재난 현장 소음에 강하다”고 확정하지 않으며,
BRIO 동시 녹음과 화자 3명 이상으로 최종 판단한다. 기존 합성 TTS 5문장 기반 Qwen
CER 0.89% 결과는 평가 도구의 예비 회귀 결과로만 보존하고 성능의 주 근거로 쓰지 않는다.

#### 질문 문맥 기반 GMS 복원 24건

토큰 사용을 제한하면서 최종 서비스 품질을 확인하기 위해 clean·siren 0dB·moto 5/0dB·
realmotor 5/0dB에서 동일한 네 발화를 선택했다. 긴급 없음, 긴급 있음, 이동 불가,
총 3명 답변으로 총 24건이며 각 전사를 운영 `gpt-5.4-mini` 프롬프트로 한 번씩만 호출했다.

| 조건 | 최종 슬롯 정답 |
|---|---:|
| clean | 3/4 |
| siren@0dB | 3/4 |
| moto@5dB | 0/4 |
| moto@0dB | 0/4 |
| realmotor@5dB | 2/4 |
| realmotor@0dB | 3/4 |
| 전체 | **11/24 (45.83%)** |

같은 전사에 키워드 폴백을 적용한 7/24(29.17%)보다 4건을 추가로 맞혔고, 핵심어가
손상된 19건 중 7건에서 최종 슬롯을 복원했다. P50/P95는 1,384.41/1,772.42ms였다.
예를 들어 `음가 계속 나요`를 긴급 있음으로, `다리가 늘려서 움직여요`를 이동 불가로
복원한 사례가 있었다.

반면 `비가 계속 나요`는 질문 문맥이 있어도 긴급 여부를 UNKNOWN으로 남겼고,
`moto@5dB`의 `팔이가 들려서 움직여요`는 실제 이동 불가 발화였지만 **이동 가능(YES)**으로
판정했다. 위험→안전 반전 1건이며 근거 없는 잘못된 확정도 이 1건이다. 따라서 GMS 질문
문맥은 일부 STT 오류를 보완하지만 잡음 제거 대책으로 간주하지 않는다. 정보가 보존되지
않은 경우 UNKNOWN을 유지하도록 안전 가드를 추가 검토해야 한다.

DeepFilterNet은 기존 실제 육성·소음 108조건 A/B에서 원음보다 정확도가 낮았으므로 현재도
STT 전처리로 채택하지 않는다. 검증된 개선은 과도한 RMS 선게이트를 0.005에서 0.001로
내려 실제 약한 발화가 Silero까지 도달하게 한 부분이며, 잡음 제거 효과로 표현하지 않는다.
전체 요약은 `ai/voice/results/noise-robustness-20260806/summary.json`에 보존한다.

### 33.13.2 L40S ASR 후보 비교

측정 환경은 NVIDIA L40S Device3 46,068MiB, driver 570.211.01, CUDA Driver API
12.8이다. 한국어·영어 합성 발화와 무음·잡음으로 구성된 9개 스모크 케이스를 모델별
3회 실행했다.

| 모델 | micro CER | micro WER | 핵심 표현 | 위험→안전 | P50 | P95 | RTF | VRAM |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Qwen3-ASR-1.7B | **0.0000** | **0.0000** | 100% | 0 | **260.667ms** | 425.847ms | **0.1024** | 5,014MiB |
| faster-whisper large-v3 | 0.0097 | 0.0645 | 100% | 0 | 417.319ms | 509.149ms | 0.1607 | 3,528MiB |
| faster-whisper large-v3-turbo | 0.0291 | 0.0968 | 100% | 0 | 302.578ms | **367.649ms** | 0.1134 | **2,170MiB** |

CER·WER는 발화별 평균이 아니라 전체 편집 수를 전체 정답 단위로 나눈 micro 값이다.
Turbo는 VRAM과 P95에서 유리했지만 Qwen이 정확도에서 우세해 운영 모델로 선정됐다.

무음·잡음에서는 세 모델 모두 헛문장을 생성한 사례가 있었다.

| 모델 | 무음 예시 | 잡음 예시 |
|---|---|---|
| Qwen3-ASR | `그렇죠.` | `그렇지.` |
| large-v3 | `한글자막 by 한효주` | `시청해주셔서 감사합니다.` |
| large-v3-turbo | `다음 영상에서 만나요.` | `다음 영상에서 만나요.` |

따라서 모델 정확도만으로 무음 환각을 방어하지 않는다. Jetson 로컬 VAD, 원본 RMS,
빈 전사·반복·에코 가드를 함께 유지한다. 합성 9건은 후보 선별용이며 실제 화자·BRIO·잔향과
약한 발성을 대표하지 않는다.

현장 승격 기준은 최소 3명 × 핵심 10발화 × quiet/noisy × normal/weak, 총 120건이다.
위험→안전 뒤집힘 0건, 숫자·부정어·이동·긴급 표현 보존과 공유 GPU 부하 P95를 함께 본다.

### 33.13.5 Jetson RAM 실측과 해석

#### 과거 로컬 LLM 구성

2026-07-24 Jetson Orin Nano 8GB, JetPack 6.2.1, 15W, 헤드리스 환경에서 측정했다.
구성은 Silero VAD + CPU int8 faster-whisper small + GPU qwen2.5:3b이며 TTS는 로드하지
않았다. `tegrastats`가 표시한 사용 가능 총량은 7.4GB였다.

| 상태 | RAM 실측 |
|---|---:|
| idle 헤드리스 | 약 1.8GB |
| VAD + 로컬 STT 상주, LLM 미로드 | 약 3.1~3.3GB |
| 로컬 3B LLM 보고 피크 | **5.62GB / 7.4GB** |
| 피크 시 여유 | 약 1.9GB |

비전·SLAM·Nav2가 쓸 수 있는 여유가 약 1.9GB뿐이어서 로컬 LLM을 제거하는 근거가 됐다.
당시 `free`가 1.3GB, buff/cache가 4.2GB, available이 5.0GB인 상태에서도 CUDA가
1.79GB 연속 버퍼를 할당하지 못해 OOM이 발생했다. Jetson nvgpu 할당에서 available만
보고 안전하다고 판단하면 안 된다는 관측이다.

#### GMS 전환 후, 로컬 Whisper가 남아 있던 구성

2026-07-30 GUI·PulseAudio를 켠 Jetson 15W 환경에서 BRIO 100과 Bluetooth A2DP를
사용해 시나리오 A 육성 세션을 측정했다. 코드는 `e36f910`, 구성은 CPU int8 Whisper
small + GMS `gpt-5.4-mini`였다.

| 항목 | 실측 |
|---|---:|
| 시작 RAM | 2,670MB |
| 최저 RAM | 2,568MB |
| 피크 RAM | **4,102MB / 7,620MB** |
| 피크 시 여유 | **3,518MB** |
| 세션 E2E | **76.8초** |

로컬 3B 구성의 5,620MB보다 약 1,518MB 낮아졌다. 그러나 이 값에는 지금은 제거된
로컬 Whisper small이 포함돼 있다.

#### 현재 원격 ASR 구성

현재 Jetson **운영 경로는** Qwen3-ASR 가중치나 로컬 STT를 로드하지 않고 Silero VAD, 오디오 처리,
HTTP 클라이언트와 상태 머신만 실행한다. 단 `ctranslate2`·`faster-whisper`는 평가 도구용 패키지로 venv에 잔존한다. 따라서 현재 구성이 과거 4,102MB보다 낮을 것으로
예상되지만, **아직 같은 조건으로 다시 측정하지 않았으므로 절감량을 확정하지 않는다.**

다음 표를 실제 Jetson에서 채워 현재 기준선을 확정한다.

| 동시 구동 조합 | 총 RAM peak | available 최소 | 음성 E2E P95 | 비전 FPS | OOM/스로틀 | 판정 |
|---|---:|---:|---:|---:|---|---|
| 음성 원격 ASR 단독 | 미측정 | 미측정 | 미측정 | — | 미측정 | 대기 |
| 비전 + SLAM | 미측정 | 미측정 | — | 미측정 | 미측정 | 대기 |
| 비전 + SLAM + 음성 | 미측정 | 미측정 | 미측정 | 미측정 | 미측정 | 대기 |
| 비전 + SLAM + Nav2 + 음성 | 미측정 | 미측정 | 미측정 | 미측정 | 미측정 | 대기 |

측정은 바퀴를 띄운 정지 통합 시험을 먼저 통과한 뒤 실제 주행으로 진행한다. OOM뿐 아니라
최소 available RAM, swap, 온도, 전력과 열 스로틀링을 함께 기록한다.

### 33.13.6 공개 한국어 STT 기준선

이 수치는 현재 Qwen3-ASR이 아니라 **과거 로컬 Whisper small의 방법론·오류율 기준선**이다.
KsponSpeech 공식 평가셋에서 라틴 문자 포함 24개와 5자 미만 505개를 제외한 2,471발화를
clean/SNR 10/5/0dB, 프롬프트 있음/없음으로 총 19,768회 인식했다.

| 조건 | CER 프롬프트 있음 | CER 없음 | WER 프롬프트 있음 | WER 없음 |
|---|---:|---:|---:|---:|
| clean | 0.141 | **0.137** | 0.305 | **0.304** |
| SNR 10dB | 0.206 | **0.188** | 0.379 | **0.361** |
| SNR 5dB | 0.259 | **0.235** | 0.434 | **0.413** |
| SNR 0dB | 0.366 | **0.352** | 0.533 | **0.495** |

모든 조건에서 도메인 프라이밍이 손해였고 프롬프트 문장이 전사로 되돌아온 사례가 57회,
무프롬프트에서는 0회였다. 현재 운영 ASR 요청에 Whisper식 도메인 프라이밍을 넣지 않는
근거다. 이 코퍼스는 정상 화자의 일반 대화이므로 재난 현장·약한 발화 성능을 증명하지 않는다.

### 33.13.7 잡음 제거 A/B

실제 육성 6개와 모터·화재·현장음·사이렌 등 소음 6종을 합성한 108조건 결과다.

| 지표 | 원본+소음 | DeepFilterNet 후처리 |
|---|---:|---:|
| CER 승리 | **58** | 16 |
| 무승부 | 34 | 34 |
| CER 중앙값 | **0.467** | 0.667 |
| 환각 발생률 | **0.9%** | 13.9% |

DeepFilterNet의 x86 처리 비용은 60초 오디오 약 1.0초, RTF 0.017, 프로세스 전체 peak
약 1.0GB였다. EC2 실측 당시 available RAM 14,091MB, 디스크 여유 297GB로 관제
청취본 후처리 서버 자원은 충분했다.

실제 아이폰 동시 녹음 1건에서는 다음 결과가 나왔다.

| 구간 | 원본 | 제거 후 | 변화 |
|---|---:|---:|---:|
| 발화 구간 RMS | -26.9dB | -31.7dB | **-4.7dB** |
| 소음 구간 RMS | -31.8dB | -50.9dB | -19.1dB |
| 발화/소음 레벨차 | 4.9dB | 19.2dB | +14.3dB |
| 1~3.4kHz 음성대역 잔존 | 100% | 5.9% | 대부분 소실 |
| 3.4~8kHz 고역 잔존 | 100% | 0.2% | 대부분 소실 |

소음은 크게 줄었지만 음성 자음 성분도 제거돼 정확했던 원본 전사가 붕괴했다. 감쇠 상한을
6~30dB로 제한해도 원본 STT를 넘지 못했다. 따라서 관제 청취 편의에는 사용할 수 있지만
STT 입력에는 사용하지 않는다.

### 33.13.8 수치 사용 시 주의사항

- 합성 음성·합성 소음 결과를 실제 재난 현장 성능으로 표현하지 않는다.
- 과거 Whisper·로컬 LLM RAM을 현재 원격 Qwen 구성의 값으로 재사용하지 않는다.
- 평균만 보고하지 않고 P50, P95, 최대, 실패 건수와 표본 수를 함께 적는다.
- CER/WER와 핵심 슬롯 정확도는 다른 지표이므로 서로 대신하지 않는다.
- 실제 사람 음성, API 키, 원본 세션과 로컬 `results/`는 Git에 커밋하지 않는다.
- 현재 구조의 최종 수치는 Jetson 전체 스택과 BRIO 현장 코퍼스 측정 후 갱신한다.
