# 음성 세션 보고 스키마

> 관련 Jira: S15P11A301-113
> 기준: 통합 명세 33-4·33-6, 대화 안전 정책

## 1. 목적

요구조자 음성 세션 결과를 Jetson, 관제 서버와 화면에서 같은 의미로
사용하기 위한 계약이다. BRIO 100 마이크 하나로 여러 사람의 화자를
구분할 수 없으므로 모든 발화는 그룹 단위로 저장한다.

## 2. 필드 설명

| JSON 필드 | 한글 의미 | 타입·허용값 | 결정 주체 |
|---|---|---|---|
| `responseScope` | 발화 정보가 적용되는 범위 | `GROUP` | 시스템 정책 |
| `anyResponseDetected` | 세션 중 사람의 음성 응답을 감지했는지 | `true`, `false`, `null` | VAD·상태머신 |
| `reportedResponsiveCount` | 발화자가 직접 말한 응답 가능 인원 수 | 0 이상의 정수, `null` | GMS·폴백 |
| `reportedCountStatus` | 인원 수의 출처와 확정 상태 | `SELF_REPORTED_GROUP_COUNT`, `CONFIRMED_BY_OPERATOR`, `UNKNOWN` | 시스템·관제 |
| `countConfidence` | 인원 수 인식 신뢰도 | 0.0~1.0, `null` | STT·검증 로직 |
| `mobilityStatus` | 그룹이 스스로 이동할 수 있다고 답했는지 | `YES`, `NO`, `UNKNOWN` | GMS·폴백 |
| `urgentConditionReported` | 심한 출혈·호흡 곤란 등 긴급 상태를 발화로 알렸는지 | `YES`, `NO`, `UNKNOWN` | GMS·폴백 |
| `operatorReviewRequired` | 관제 담당자의 최종 확인이 필요한지 | `true`, `false` | 안전 정책 |
| `terminationReason` | 음성 세션이 종료된 이유 | 아래 종료 사유 표 참조 | 상태머신 |

`null`과 `UNKNOWN`의 의미는 다르다.

- `null`: 값을 관찰하거나 계산할 수 없었음
- `UNKNOWN`: 질문은 처리했지만 답을 확정할 수 없었음

## 3. 종료 사유

| 값 | 의미 |
|---|---|
| `NORMAL` | 질문 흐름을 정상적으로 마침 |
| `TIMEOUT` | 세션 제한 시간을 초과함 |
| `ABORTED_MANUAL` | 작업자가 수동으로 중단함 |
| `ABORTED_SAFETY` | 로봇 또는 현장 안전 조건으로 중단함 |
| `AUDIO_DEVICE_ERROR` | 마이크 열기·녹음 등 오디오 장치 오류 |
| `GMS_UNAVAILABLE` | GMS를 사용할 수 없어 세션을 종료함 |
| `UNKNOWN` | 아직 종료되지 않았거나 이유를 확정하지 못함 |

## 4. 책임 분리

GMS와 키워드 폴백은 발화 내용에서 다음 세 필드만 추출한다.

```json
{
  "reportedResponsiveCount": 2,
  "mobilityStatus": "NO",
  "urgentConditionReported": "UNKNOWN"
}
```

다음 필드는 GMS가 생성하지 않는다.

- `responseScope`: 단일 마이크 정책에 따라 시스템이 `GROUP`으로 고정
- `anyResponseDetected`: VAD와 상태머신이 결정
- `reportedCountStatus`: 시스템 또는 관제가 결정
- `countConfidence`: 실제 STT·검증 수치가 있을 때만 기록
- `operatorReviewRequired`: 안전 정책이 결정
- `terminationReason`: 상태머신이 결정

## 5. 보고 예시

### 정상 세션

```json
{
  "responseScope": "GROUP",
  "anyResponseDetected": true,
  "reportedResponsiveCount": 2,
  "reportedCountStatus": "SELF_REPORTED_GROUP_COUNT",
  "countConfidence": null,
  "mobilityStatus": "NO",
  "urgentConditionReported": "UNKNOWN",
  "operatorReviewRequired": true,
  "terminationReason": "NORMAL"
}
```

### 오디오 장치 오류

```json
{
  "responseScope": "GROUP",
  "anyResponseDetected": null,
  "reportedResponsiveCount": null,
  "reportedCountStatus": "UNKNOWN",
  "countConfidence": null,
  "mobilityStatus": "UNKNOWN",
  "urgentConditionReported": "UNKNOWN",
  "operatorReviewRequired": true,
  "terminationReason": "AUDIO_DEVICE_ERROR"
}
```

오디오 오류에서는 `anyResponseDetected=false`를 사용하지 않는다. 실제로
사람이 응답하지 않은 것이 아니라 시스템이 응답 여부를 관찰하지 못했기 때문이다.

## 6. 제외한 정보

- 통증 부위·진단명: 현재 질문 흐름의 수집 대상이 아니며 의료 추론 위험이 있음
- ETA: 관제 서버가 승인한 값만 별도 안내하며 GMS가 생성하지 않음
- 특정 피해자 ID: 단일 마이크로 화자를 식별할 수 없어 자동 귀속하지 않음
- GMS/폴백 출처: 세션 필드가 아니라 각 turn의 `llm_model_version` 또는
  `parse_status`에 기록
- 위험도 참고값: 세션 원본 관찰값에서 별도로 계산하며 원본 보고 필드와 분리

위험도 참고값을 정식 의료 triage 또는 최종 구조 순위로 사용하지 않는
근거와 관제 전문가의 결정 권한은
[`대화-안전-정책.md`](대화-안전-정책.md)의
“정식 의료 triage로 표현하지 않는 이유”를 따른다.
