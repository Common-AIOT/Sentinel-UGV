## 1. 시험 단계와 크레딧 절감 원칙

모든 후보를 처음부터 20문장·3회 반복하면 총 300회 호출이 필요하다. 단순
3필드 추출 작업에서 이 비용은 과하므로 다음 단계로 분리했다.

| 단계 | 목적 | 예정 호출 |
|---|---|---:|

### 4.2 Anthropic 모델 형식 문제

Sonnet과 Haiku는 각각 다섯 응답 모두 세 필드 값을 정확하게 생성했지만 JSON을
다음과 같은 Markdown 코드블록으로 감쌌다.

````text
```json
{"reportedResponsiveCount":2,"mobilityStatus":"NO","urgentConditionReported":"YES"}
```
````

최초 프로그램은 응답 전체를 `json.loads()`로 바로 읽어 코드블록 응답을 거부했다.
최종 후보 비교 전 벤치마크의 모든 공급자 응답에 동일한 최소 전처리를 추가했다.

- 응답 전체를 감싼 단일 ` ```json … ``` ` 또는 ` ``` … ``` `만 제거한다.
- 앞뒤 설명문, 중첩 코드블록, 추가 필드, 깨진 JSON은 계속 실패 처리한다.
- 전처리 후에도 정확히 세 필드만 허용하는 스키마 검증을 수행한다.

저장된 최초 원본을 새 전처리로 다시 검증하면 두 모델 모두 5/5 파싱에 성공한다.

| 모델 | 요청 성공률 | 최초 파싱 | 현재 파싱 | 슬롯 정확도 | 평균 총 토큰 | 평균 크레딧 | P50 | P95 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `claude-haiku-4-5-20251001` | 5/5 | 0/5 | 5/5 | 15/15 | 496 | 6.32 | 0.99초 | 1.43초 |
| `claude-sonnet-4-6` | 5/5 | 0/5 | 5/5 | 15/15 | 496 | 18.96 | 1.87초 | 2.51초 |

Mini의 위험→안전 오판은 우연한 1회 오답이 아니라 5회 모두 재현됐다. Haiku는 그룹 내
이동 불가 정보를 `NO`로 확정하지 못하고 보수적으로 `UNKNOWN`을 반환했지만,
위험한 `YES` 반전과 환각은 발생하지 않았다.

### 5.6 모델 선정

`gpt-5.4-mini`는 안전 핵심 문장에서 위험→안전 오판이 반복되어 운영 후보에서 제외한다.
`claude-haiku-4-5-20251001`은 당시 전체 20문장 정확도 98.33%, 완전 일치율 95%,
위험→안전 오판 0건이며 안전 반복 시험에서도 동일 오판 0건과 출력 일관성
100%를 유지했다.

이 결과만으로는 `claude-haiku-4-5-20251001`이 우세했다. 이후 그룹 이동과 긴급
상태 규칙을 프롬프트에 명시한 v2 비교에서 결과가 달라졌으므로 최종 선정은 아래
추가 검증까지 함께 판단한다.

#### 6.11.1 지원 범위 확정: 사투리 제외

40문항 실행 후 팀 결정으로 사투리를 현재 제품 지원·평가 범위에서 제외했다. 다음
2문항은 원본 결과와 실제 크레딧 기록에는 남기되 운영 성능 점수에서는 제외한다.

- `mobility-dialect-immobilized`
- `dialect-count`

이 결정은 모델 결과 확인 후 이루어졌으므로 실행 전 제외와 구분해 기록한다. 특정
모델의 오답만 제거한 것이 아니라 두 모델의 동일한 사투리 문항 전체를 제거했다.
실제 API 호출 수와 지출은 80회 그대로이며, 공식 운영 범위 점수만
`38문항 × 2모델 = 76결과`로 다시 계산한다.

검토가 끝난 원본 4개 파일은
`bench/fixtures/gms-external-independent-v2.json` 하나로 통합했다. 공식 평가
38문항은 `cases`, 제외 18문항은 `excludedCases`에 분리해 이후 벤치에서 부적합
문항이 실수로 호출되지 않게 했다. 통합 파일 SHA-256은

#### 6.11.5 최종 운영 모델 선정

Jira S15P11A301-118의 최종 GMS 정보 추출 모델은 **GPT-5.4 Mini**로 선정한다.

선정 근거는 다음과 같다.

- Mini의 완전 일치율은 `36/38(94.74%)`로 Opus의 `37/38(97.37%)`보다 1건
  낮았고, 슬롯 정확도도 `112/114`로 1개 낮았다.
- Mini의 평균 크레딧은 `10.1586`으로 Opus `66.5395`의 약 15.3%이며,
  Opus가 약 6.55배 더 많은 크레딧을 사용했다.
- Mini의 P95 응답시간은 `2.12초`로 Opus `3.33초`보다 약 1.21초 짧았다.
- 두 모델 모두 `위험→안전 오판`이 0건이었으므로, 이번 고정 표본에서는 Opus의
  비용 증가를 정당화할 안전상 우위가 확인되지 않았다.
- Haiku는 Mini보다 완전 일치율과 슬롯 정확도가 낮고 평균 크레딧도 높아 운영
  후보에서 제외한다.

따라서 **정확도·안전성·응답시간·크레딧을 종합하면 Mini가 가장 균형적인 운영
모델**이다. Opus는 높은 정확도가 반드시 필요한 후속 실험의 비교 기준으로
보존하되 기본 운영 모델로 사용하지 않는다.

이 결정은 고정된 표준 한국어 38문항의 GMS 정보 추출 결과에 대한 것이다. 실제
BRIO 100 음성과 STT 오류가 포함된 종단 간 현장 성능은 Jira S15P11A301-120에서
별도로 검증하며, 이는 이번 모델 선정 완료 여부를 보류하는 조건이 아니다.

#### 6.11.7 응답 가능 인원 계약 전수검사

질문 문구와 테스트 기대값의 화자 포함 여부를 전수검사했다. 기준은
“화자 본인을 포함해 발화자가 직접 보고한 음성 응답 가능 총인원”이다.

- 외부 표준 한국어 38문항의 인원 기대값은 이 기준과 모두 일치했다.
- 기존 `gms-extraction-cases.json`의 `count-0` 한 건은 화자가 답하고 있는데
  주변에 다른 응답자가 없다는 말을 `0`으로 기록해 기준과 충돌했다.
- Mini와 Haiku가 서로 다른 두 실행에서 모두 `0`을 출력한 것은 개별 모델의
  우연한 오답보다 당시 프롬프트·질문·라벨이 화자를 제외하도록 해석될 수 있었다는
  계약 설계 문제의 근거로 본다.
- 해당 문항을 `count-speaker-only-negative`로 바꾸고 기대값을 `1`로 수정했다.
- 질문 문구, GMS 프롬프트, 키워드 폴백, 보고 스키마도 본인 포함 기준으로 통일했다.
- 단순히 발화에 등장한 사람 수는 응답 가능 여부가 확인되지 않으면 합산하지 않는다.

이 수정으로 `gms-extraction-cases.json` 버전은 `voice-gms-bench-v1.1`이 됐다.
이전 v1.0 원본 출력에서 두 모델 모두 `0`을 반환했다. 하지만 당시 프롬프트에는
화자 포함 규칙이 없었고 당시 라벨도 `0`이었으므로 이를 모델 오답으로 소급
재채점하지 않는다. 과거 점수는 당시 계약의 재현 기록으로만 보존하고, 새 계약의
정확도는 수정된 프롬프트와 v1.1 문항으로 다시 호출해 측정한다. 외부 38문항에는
이 문항이 없어 Mini·Haiku·Opus 비교 수치는 변경되지 않았다.
