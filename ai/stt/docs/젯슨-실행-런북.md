## ⚠️ 시작 전 반드시: 시계 확인

이 보드는 **RTC 배터리가 없어 전원이 끊기면 시계가 과거로 리셋**됩니다. 시계가 틀리면
TLS 검증이 깨져 **모든 다운로드(pip·ollama·HF·Docker)가 401/인증 오류**로 실패합니다.
부팅 후 제일 먼저:

```bash
timedatectl status   # System clock synchronized: no 이거나 날짜가 틀리면 ↓
sudo date -s "YYYY-MM-DD HH:MM:SS"   # 실제 현재 시각으로 (폰 시계 참고)
```

> 교내망은 NTP(UDP 123)가 막혀 자동 동기화가 안 됩니다. 수동 설정이 정답입니다.

```bash
sudo fallocate -l 8G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile \
```

## Phase 1 — 파이썬 환경 (최초 1회)

**venv는 레포 루트에** 만들고, 이후 모든 작업 전에 활성화합니다.

```bash
cd ~/projects/S15P11A301 && python3 -m venv .venv
source .venv/bin/activate && pip install -U pip
```

### 1-1. Jetson용 PyTorch — 인덱스 URL에 `/+simple/` 필수

일반 `pip install torch`는 ARM64+CUDA 휠이 없어 실패합니다. jetson-ai-lab 인덱스를 쓰되,
**경로 끝에 `/+simple/`이 없으면 "No matching distribution" 에러**가 납니다 (실제로 겪음).

```bash
pip install torch==2.8.0 torchaudio==2.8.0 \
  --index-url https://pypi.jetson-ai-lab.io/jp6/cu126/+simple/
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"  # → 2.8.0 True
```

### 1-2. numpy는 반드시 1.x

Jetson torch 휠은 numpy 1.x 기준 빌드라, pip이 넣어주는 numpy 2.x와 충돌해
`torch.from_numpy`가 깨집니다(VAD 경로 사망). **torch 설치 후 강제 다운그레이드:**

```bash
pip install "numpy<2"
python -c "import torch, numpy; print(torch.from_numpy(numpy.zeros(3)))"  # 경고 없이 tensor 출력이면 OK
```

### 1-3. 나머지 의존성 — melotts 제외

`melotts` PyPI 패키지(0.1.1)는 패키징 버그로 빌드가 실패합니다. **빼고 설치**합니다
(TTS는 사전녹음 방식이라 젯슨에 불필요 — [`메모리-예산.md`](메모리-예산.md) §5 1순위).

```bash
sudo apt install -y portaudio19-dev libsndfile1
pip install sounddevice soundfile scipy librosa faster-whisper silero-vad openai
```

### 1-4. LLM — GMS API (팀 결정 2026-07-24, 젯슨에 모델 미탑재)

실측 결과(로컬 3b 피크 5.62GB·page cache OOM)에 따라 LLM은 **GMS API(gpt-5-nano) 호출**로
확정. `openai` 패키지는 requirements.txt에 포함되어 있고, 키만 설정하면 된다:

```bash
cd ~/projects/S15P11A301/ai/stt
echo "GMS_KEY=여기에_팀_GMS_키" > .env    # 커밋 금지(.gitignore 등록됨)
```

- 오프라인/호출 실패 시 `llm.py`가 **명세 33-8 키워드 폴백**으로 자동 전환 — 핵심 보고는 유지된다.
- (참고) 구 절차였던 ollama+qwen2.5:3b 는 더 이상 필요 없음. 설치돼 있다면
  `sudo systemctl disable --now ollama` 로 꺼서 RAM을 아껴도 된다.

## Phase 2 — 코드 + 가중치 캐싱 (온라인 상태에서)

```bash
cd ~/projects/S15P11A301 && git fetch origin \
  && git checkout feature/ai/S15P11A301-69-voice-pipeline && git pull
```

## Phase 3 — 단독 벤치 (단계 1, 로봇 정지)

### 3-1. LLM 로드 전 page cache 비우기 (중요)

**여유 RAM이 있어 보여도 page cache가 차 있으면 LLM GPU 로드가 OOM으로 실패**합니다
(젯슨 nvgpu 할당기는 캐시를 회수하지 못함 — 상세: [`메모리-예산.md`](메모리-예산.md) §3).

```bash
sudo sh -c 'sync; echo 3 > /proc/sys/vm/drop_caches'
free -h    # free가 수 GB로 올라왔는지 확인
```

측정 대표성을 높이려면 헤드리스 전환(SSH 접속 상태에서만!):

```bash
sudo systemctl isolate multi-user.target     # GUI 종료 (복구: graphical.target)
# (구) ollama 사용 시절엔 여기서 재시작이 필요했음 — GMS 전환 후 해당 없음
```

### 3-2. 측정 실행

터미널 2개:

```bash
# 터미널 A — RAM 로깅
tegrastats --interval 1000 | tee ~/bench_ram.log

# 터미널 B — 벤치 (-u 필수: 없으면 tee 버퍼링 때문에 멈춘 것처럼 보임)
cd ~/projects/S15P11A301/ai/stt
SENTINEL_DEVICE=cpu python -u bench/pipeline_bench.py 2>&1 | tee ~/bench_console.log
```

끝나면 피크 추출:

```bash
grep -oE 'RAM [0-9]+/[0-9]+MB' ~/bench_ram.log | awk -F'[ /]' '{print $2}' | sort -n | tail -1
```

- `data/`에 wav 샘플이 없으면 시나리오는 `NO_FILE` 스킵 — **RAM·모델 로드 검증은 가능**,
  지연·정확도는 샘플 필요(개발 PC에서 scp로 이관).
- 산출물: `results/pipeline_bench_*.csv` + 로그 2종. 결과는 [`메모리-예산.md`](메모리-예산.md)에 기입.

## 트러블슈팅 — 실제로 겪은 함정들

| 증상 | 원인 / 해결 |
|---|---|
| pip·ollama·docker 전부 401/인증 오류 | **시계가 과거로 리셋됨** (RTC 배터리 없음) → `sudo date -s "..."` 후 재시도 |
| `pip install torch` → No matching distribution | 인덱스 URL에 **`/+simple/` 누락** → 1-1의 전체 URL 사용 |
| torch import 시 NumPy 경고 + `Failed to initialize NumPy` | numpy 2.x 충돌 → `pip install "numpy<2"` |
| `pip install -r requirements.txt` 중 melotts 빌드 실패 | PyPI 패키징 버그 → melotts 빼고 설치 (1-3) |
| `[FAIL] STT 로드: CTranslate2 not compiled with CUDA` | ARM64 CTranslate2에 CUDA 빌드 없음 → `SENTINEL_DEVICE=cpu` |
| LLM 로드 시 `cudaMalloc failed: out of memory` | **page cache가 free를 잠식** → `drop_caches` (3-1). available이 커도 발생함 |
| (구) `Failed to connect to Ollama` | ollama 시절 이슈 — GMS 전환으로 해당 없음. GMS 실패는 33-8 폴백으로 처리됨 |
| 벤치가 멈춘 것처럼 보임 (`tee` 사용 시) | 파이썬 stdout 버퍼링 → `python -u`로 실행 |
| `jtop`: "I can't access jtop.service" | 그룹 미적용 → `newgrp jtop` (재부팅 금지) |
| 재부팅 후 느려짐 | `jetson_clocks`는 부팅마다 초기화 → 재실행 |
| (참고) jetson-containers/l4t-pytorch 이미지 | **비추천** — 압축 6.3GB/해제 19.6GB로 디스크 초과 + Docker Hub 인증 만료로 대용량 pull 반복 실패. 네이티브 설치(Phase 1)가 정답이었음 |

**환경변수:** `SENTINEL_DEVICE=cpu`(필수) · `SENTINEL_STT_MODEL`(기본 small) · `SENTINEL_LLM`(기본 gpt-5-nano) · `GMS_KEY`(.env, 필수)
