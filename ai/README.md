# AI

재난 현장에서 **비전(Vision)의 사각지대를 메우는 온디바이스 음성 지능** 파트입니다.
카메라가 보지 못하는 요구조자(잔해 뒤, 어두운 곳)를 **소리와 대화**로 파악해
부상 정보를 구조화하고 관제 서버에 보고합니다.

- **온라인 음성 세션에서 STT·VAD는 Jetson 로컬**, **LLM은 GMS API(gpt-5-nano) 호출**입니다(팀 결정 2026-07-24).
  - 전환 근거: 젯슨 실측에서 로컬 LLM(qwen2.5:3b) 피크 5.62GB·page cache OOM — [`stt/docs/메모리-예산.md`](stt/docs/메모리-예산.md)
  - **네트워크 단절이 확인되면 신규 STT 대화를 시작하지 않습니다.** 안전 안내 음성만 재생하고 관제 전송을 대기열에 보관합니다.
  - 이미 STT가 끝난 뒤 GMS 호출만 실패한 경우에 한해 명세 33-8 축소안(키워드 파서)을 사용합니다([`stt/llm.py`](stt/llm.py)).
- TTS는 **사전녹음 wav 재생**(고정 안내 문구, RAM 절약 1순위). MeloTTS는 개발 PC에서 wav 생성용.
- Orin Nano 8GB는 비전(YOLO)·SLAM·Nav2와 자원을 나눠 쓰므로 **경량화**가 전제입니다.

## 구성

- [`stt/`](stt/) — **음성 파이프라인**: 트리거 → VAD → STT → LLM(정보 구조화) → 규칙 triage → 관제 보고 → 안내 음성(TTS)

> SED(비언어 소리 이벤트 탐지)는 검증 부담과 시연 핵심도를 고려해 **현재 시나리오에서 제외**되었습니다.
> 트리거는 비전(객체 탐지)이 기본이며, 향후 SED를 다시 넣을 경우 별도 서브시스템으로 추가합니다.

## 설계 원칙

1. **LLM은 진단하지 않는다** — 관찰된 사실만 JSON으로 구조화하고, 심각도 등급은 규칙으로 산출(재현·설명 가능). 최종 판단은 관제의 사람.
2. **무응답과 시스템 실패를 구분한다** — 정상적으로 질문을 재생하고 청취한 경우에만 무응답을 관찰값으로 기록합니다. STT·마이크·네트워크 실패를 요구조자 무응답으로 분류하지 않습니다.
3. **측정 우선** — 모델 확정 전에 RAM/지연/정확도를 수치로 측정하고, 안 되면 다운시프트.

세부 실행·설치·젯슨 최적화는 [`stt/README.md`](stt/README.md)를 참고하세요.
