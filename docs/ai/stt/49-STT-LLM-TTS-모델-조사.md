# 49. STT·LLM·TTS 모델 조사

> Jira: S15P11A301-49 · 상태: 완료
> 설계 기준: 33장 피해자 음성 상호작용([04-자율주행-AI.md](../../04-자율주행-AI.md) 내)

네트워크가 끊긴 재난 현장에서 요구조자의 음성을 듣고 부상 정보를 구조화해 관제에 보고하는
**온디바이스 음성 파이프라인**을 구성하기 위한 사전 조사 결과입니다. 모든 모델은
Jetson Orin Nano에 로컬로 올리는 것을 전제로 하며, 후속 [모델 테스트](50-STT-LLM-TTS-모델-테스트.md)의 후보를 선정합니다.

## 49-1. 하드웨어 전제

하드웨어는 **Jetson Orin Nano 8GB**(Ampere 1024코어 + Tensor 코어, ~40 TOPS)이다.
구형 Jetson Nano(4GB, Maxwell)와 전혀 다른 급으로, **양자화된 소형 LLM + Whisper STT + TTS를 실제로 구동**할 수 있다.
단, 비전(YOLO)·SLAM·Nav2와 8GB RAM/GPU를 나눠 써야 하므로 오디오 파이프라인 예산을 **2~3GB 이내**로 설계한다.

## 49-2. 역할 분리 — STT ≠ 소리 탐지

| 대상 | 상태 | 필요 기술 |
|---|---|---|
| 의식 있는 요구조자 | 말을 할 수 있음 | STT → LLM → TTS |
| 잔해에 깔린/의식 저하 | 신음·기침·호흡·두드림만 냄 | SED(Sound Event Detection) |

- **STT**는 "단어"를 받아쓴다. 비언어 소리(신음·비명)는 대상이 아니다.
- **SED**는 비언어 인간 소리를 분류하는 별도 서브시스템(후보: YAMNet 초경량, PANNs, BEATs/AST)이다.
- 마이크 어레이(ReSpeaker 등)를 쓰면 방향 추정(DOA)으로 소리 나는 사람을 지도에 표시할 수 있으나, **비용 문제로 이번 범위에서는 채택하지 않는다**(단일 USB 마이크 전제).

> SED는 조사 단계에서 별도 서브시스템으로 검토했으나, 검증 부담과 시연 핵심도를 고려해
> 이후 [테스트 단계](50-STT-LLM-TTS-모델-테스트.md)에서 **시나리오에서 제외**하기로 결정한다.

## 49-3. 파이프라인 개요

```text
[트리거: 비전 객체탐지] → 로봇 정지
   → ① VAD(노이즈/무음 컷)
   → ② STT(텍스트 + 신뢰도)
   → ③ LLM(정보 구조화, 진단 아님)
   → ④ 규칙 triage(등급 산출)
   → ⑤ 관제 서버 보고(WebSocket)
   → ⑥ 안내 음성(사전녹음 또는 동적 TTS)
```

## 49-4. 후보 모델 조합

| 조합 | STT | LLM | TTS | 특징 |
|---|---|---|---|---|
| A(초경량) | faster-whisper tiny/base(int8) | Qwen2.5-1.5B(Q4) | Piper/사전녹음 | 자원 최소, 노이즈·약한발화에서 정확도 타협 |
| **B(균형, 추천)** | **faster-whisper small(int8)** | **EXAONE 3.5 2.4B / Qwen2.5-3B(Q4)** | Piper/MeloTTS + 사전녹음 | 한국어·정확도·자원 균형, 시연 안정성 높음 |
| C(고품질) | whisper large-v3-turbo/medium | Qwen2.5-3B / Phi-3.5-mini | XTTS-v2 | 최고 인식률, 8GB 동시구동 시 OOM·발열 위험 |

→ **조합 B로 측정을 시작**하고, 필요 시 A로 축소하거나 C로 부분 상향하는 전략을 채택한다.

## 49-5. 핵심 설계 고려사항

1. **로봇 자체 소음(ego-noise)** — 무한궤도는 시끄러워 미세한 음성을 덮는다. 정밀 청취 시 **로봇을 완전 정지**시키는 "정지 후 청취" 설계가 필수.
2. **LLM 환각은 의료 판단에서 치명적** — LLM은 "진단"이 아니라 **"정보 구조화(추출)"**로 한정. 최종 판단은 관제의 사람이 한다.
3. **노이즈 오입력 방어** — VAD로 1차 컷, STT 신뢰도로 2차 컷.
4. **"무응답"도 중요한 의료 정보** — 소리는 감지됐는데 유효 응답이 없으면 **"무반응(중증)"**으로 보고(triage 최고 위험도).
5. **심각도는 규칙으로 산출** — LLM 자유판단 대신 START/AVPU를 단순화한 구조화 항목을 규칙으로 등급화(재현·설명 가능).
6. **피크 메모리 관리** — STT/LLM/TTS는 순차(turn-based) 실행이므로 동시 로드하지 않는다. 정형 안내는 사전녹음으로 자원 절약.

### 구조화 항목(추출 스키마)

| 항목 | 값 |
|---|---|
| consciousness (의식) | 명료 / 혼미 / 통증반응 / 무반응 / 미확인 |
| speech (발화 가능성) | 완전문장 / 단어만 / 신음만 / 불가 / 미확인 |
| pain_location (통증부위) | 발화에 나온 신체부위 배열 |
| hazard (환경위험) | 가스 / 불 / 연기 / 붕괴 등 |
| can_move (이동 가능) | 가능 / 불가 / 미확인 |
| additional_victims (추가부상자) | 인원수 |

## 49-6. 결론

- 하드웨어는 Orin Nano → 소형 LLM 로컬 구동 가능.
- STT와 SED는 역할이 다른 별개 시스템(SED는 이후 범위에서 제외).
- **조합 B(faster-whisper small + Qwen2.5-3B/EXAONE 2.4B + TTS + VAD)**부터 실측으로 검증한다.
