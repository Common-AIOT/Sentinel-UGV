# GMS 정보 추출 모델 비교 런북

> Jira: S15P11A301-118  
> 범위: GMS 후보 모델의 구조화 정보 추출 정확도·지연·일관성·사용량 비교  
> 제외: STT 품질, Jetson RAM, 실제 요구조자 개인정보, 의료 triage 판단
>
> 용어: [`음성-파이프라인-용어집.md`](음성-파이프라인-용어집.md)

## 1. 비교 목적

음성 파이프라인에서 LLM은 자유로운 답변이나 의료 판단을 생성하지 않는다.
STT 문장에서 다음 세 가지 사실만 JSON으로 추출한다.

| 필드 | 의미 |
|---|---|
| `reportedResponsiveCount` | 화자 본인을 포함해 발화자가 직접 보고한 응답 가능 총인원 |
| `mobilityStatus` | 그룹 내 자력 이동 불가능자가 있는지를 반영한 이동 가능 여부 |
| `urgentConditionReported` | 심한 출혈·호흡 곤란 등 긴급 상태의 명시적 자기보고 여부 |

외부 AI로 생성한 4개 JSON을 검토·통합한 표준 한국어 독립 평가 세트는
`bench/fixtures/gms-external-independent-v2.json`이다. 이 파일의 `cases`에는 공식
평가 대상 38개만 있으며, 모호하거나 사투리인 18개는 `excludedCases`에 출처와
제외 이유만 보존한다. 따라서 별도의 `--case-id` 필터 없이 실행해도 제외 문항은
API 호출에 포함되지 않는다.

따라서 모델은 일반적인 대화 능력이 아니라 다음 순서로 선정한다.

1. 위험→안전 오판이 없는가
2. 발화에 없는 사실을 생성하지 않는가
3. 세 필드를 정확히 추출하는가
4. JSON 계약을 안정적으로 지키는가
5. 허용 지연 안에서 일관되게 응답하는가
6. 위 조건을 충족하는 모델 중 사용량이 합리적인가

## 2. 후보 모델

기본 비교 목록은 다음과 같다.

1. `gpt-5-nano`
2. `gemini-3.5-flash`
3. `claude-haiku-4-5-20251001`
4. `claude-sonnet-4-6`
5. `claude-opus-4-8`
6. `gpt-5.4-mini`
7. `gpt-5.4-nano`

Claude는 Anthropic Messages API용 GMS 엔드포인트, Gemini는 Google
`generateContent`용 GMS 엔드포인트를 사용한다. GPT 계열만 OpenAI 호환
엔드포인트를 사용한다.

이는 팀의 비교 희망 모델명이다. GMS가 노출하는 실제 모델 ID와 다를 수 있으므로,
401·403·404 또는 모델 미지원 오류가 발생하면 임의로 다른 모델로 대체하지 않는다.
오류 결과를 보존하고 GMS 모델 목록 또는 팀 제공 문서에서 정확한 ID를 확인한다.

### 2.1 GMS 제공 명세

다음 값은 2026-07-29에 팀이 제공한 GMS 모델 안내 문서의 명세다. 크레딧 단가는
토큰 1개 기준이며, 실제 차감량은 입력과 출력 토큰에 각각의 단가를 곱해 합산한다.
모델 소개 문구는 선정 근거로 사용하지 않고 실측 결과와 구분한다.

| 모델 ID | 제공사 | 컨텍스트 한도 | 최대 출력 | 입력 단가 | 출력 단가 | 현재 시험 상태 |
|---|---|---:|---:|---:|---:|---|
| `gpt-5-nano` | OpenAI | 400,000 | 128,000 | 0.0005 | 0.004 | 1차 선별 완료 |
| `gpt-5.4-nano` | OpenAI | 400,000 | 128,000 | 0.004 | 0.01875 | 1차 선별 완료 |
| `gpt-5.4-mini` | OpenAI | 400,000 | 128,000 | 0.015 | 0.0675 | 1차 선별 완료 |
| `gemini-3.5-flash` | Google | 1,000,000 | 65,000 | 0.015 | 0.09 | 1차 선별 완료 |
| `claude-haiku-4-5-20251001` | Anthropic | 200,000 | 64,000 | 0.01 | 0.05 | 1차 선별 완료 |
| `claude-sonnet-4-6` | Anthropic | 1,000,000 | 64,000 | 0.03 | 0.15 | 1차 선별 완료 |
| `claude-opus-4-8` | Anthropic | 1,000,000 | 128,000 | 0.05 | 0.25 | 1차 선별 완료 |

> Gemini 안내문의 소개 문장에는 “200만 토큰 컨텍스트”라고 적혀 있지만 같은 문서의
> 명시적 입력 토큰 한도는 `1,000,000`이다. 이 문서에서는 명시적 한도를 기록했으며,
> 대용량 입력이 필요하면 GMS 측에 실제 제한을 별도로 확인한다.

공급자별 GMS 호출 규격은 다음과 같다.

| 제공사 | 메서드 및 엔드포인트 | 인증 헤더 |
|---|---|---|
| OpenAI | `POST https://gms.ssafy.io/gmsapi/api.openai.com/v1/chat/completions` | `Authorization: Bearer $GMS_KEY` |
| Google | `POST https://gms.ssafy.io/gmsapi/generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` | `x-goog-api-key: $GMS_KEY` |
| Anthropic | `POST https://gms.ssafy.io/gmsapi/api.anthropic.com/v1/messages` | `x-api-key: $GMS_KEY`, `anthropic-version: 2023-06-01` |

## 3. 공정한 비교 조건

- 모든 모델에 동일한 프롬프트 파일을 사용한다.
- 모든 모델에 동일한 합성 발화 20건을 같은 반복 횟수로 입력한다.
- `gpt-5-nano`에는 빈 응답 방지를 위해 운영 코드와 같은
  `reasoning_effort=minimal`을 적용한다. `gpt-5.4` 계열은 GMS가 허용하는 최저값
  `none`을 사용한다. Gemini·Claude에는 해당 OpenAI 전용 옵션을 보내지 않는다.
- Gemini 3.5 Flash는 단순 3필드 추출에서 기본 Thinking이 출력 토큰을 소진하지
  않도록 `thinkingBudget=0`을 사용한다. 300토큰 한도에서 기본 설정을 사용한
  사전 시험은 Thinking 289토큰을 소비하고 `MAX_TOKENS`로 끝나 불완전 JSON을
  반환했다.
- 공급자와 무관하게 응답 전체를 감싼 단일 Markdown JSON 코드블록만 제거한다.
  앞뒤 설명문·중첩 코드블록은 제거하지 않으며, 전처리 후에도 정확히 세 필드만
  허용하는 스키마 검증을 통과해야 한다.
- 기본 반복 횟수는 문장당 3회다.
- STT 오차가 모델 비교에 섞이지 않도록 확정된 텍스트를 직접 입력한다.
- warm-up은 품질 집계에 포함하지 않는다. 현재 도구는 별도 warm-up을 수행하지 않는다.
- 모델별 요청을 순차 실행하므로 실행 시간대의 네트워크 변동 가능성을 결과 해석에 명시한다.
- GMS 키, 인증 헤더, 실제 요구조자 발화는 결과에 기록하지 않는다.

모든 모델을 처음부터 `20문장 × 3회` 실행하지 않는다. 다음 단계형 선별을 사용한다.

| 단계 | 실행 | 호출 수 |
|---|---|---:|
| 연결 확인 | 최초 5개 모델당 핵심 1문장 × 1회 | 5 |
| 1차 선별 | 최초 5개 모델당 핵심 5문장 × 1회 | 25 |
| Sonnet 추가 선별 | 동일 핵심 5문장 × 1회 | 5 |
| Sonnet 토큰 기록 재측정 | 동일 핵심 5문장 × 1회 | 5 |
| Haiku 추가 선별 | 동일 핵심 5문장 × 1회 | 5 |
| 최종 후보 비교 | Mini·Haiku × 남은 15문장 × 1회 | 30 |
| 안전 핵심 반복 | Mini·Haiku × 오류 사례 2문장 × 5회 | 20 |
| 프롬프트 v2 고난도 비교 | Mini·Haiku × 변형 8문장 × 3회 | 48 |
| 프롬프트 v2 전체 회귀 | Mini·Haiku × 기존 20문장 × 1회 | 40 |
| 합계 | 현재까지 실제 실행 | **183** |

Opus처럼 비싼 모델은 1차에서 명확한 우위가 없으면 최종 비교에서 제외한다. CLI는
실제 호출 전에 예정 요청 수를 출력하며 `--confirm-live`가 없으면 호출하지 않는다.
Haiku 추가 선별 5회는 2026-07-29에 완료했다.

개선 프롬프트로 기존 20문장을 Mini와 Haiku에 각각 1회 입력하는 전체 회귀 검증을
완료했다. 당시 계약에서 Mini는 20/20 완전 일치와 위험→안전 오판 0건이며,
고난도 변형 24/24 결과까지 합쳐 최종 모델로 선정했다. 화자 본인 포함으로 바뀐
새 계약의 정확도는 과거 출력을 소급 재채점하지 않고 라이브 회귀로 별도 측정한다.

## 4. 평가 지표

| 지표 | 계산 및 의미 |
|---|---|
| 요청 성공률 | 정상 응답 수 / 전체 요청 수 |
| 파싱 성공률 | 공통 코드블록 전처리 후 JSON을 읽고 필드 구조까지 검증한 수 / 전체 요청 수 |
| 슬롯 정확도 | 정확한 필드 수 / 전체 필드 수 |
| 완전 일치율 | 세 필드가 모두 정답인 응답 비율 |
| 환각 슬롯 수 | 정답이 `null`·`UNKNOWN`인데 모델이 사실값을 생성한 필드 수 |
| 위험→안전 오판 | 이동 불가→가능, 긴급 상태 있음→없음으로 뒤집은 건수 |
| P50·P95·최대 지연 | 성공 요청의 GMS 왕복시간 |
| 평균 총 토큰 | GMS가 usage를 제공하는 경우의 요청당 평균 토큰 |
| 오류 건수 | 인증·모델 미지원·할당량·서버·파싱 오류 등 |

위험→안전 오판은 평균 점수와 별도로 판단하며 목표는 0건이다. 모델이 발화에 없는
구조 ETA, 의료 진단, 최종 구조 순위를 출력하는지는 프롬프트·원본 응답 검토 항목이다.

## 5. 실행 과정

Miniforge Prompt에서 실행한다.

```bat
conda activate sentinel-audio
cd C:\Users\SSAFY\Desktop\S15P11A301\ai\stt
```

먼저 API를 호출하지 않는 검사를 수행한다.

```bat
python -m bench.gms_model_bench --dry-run
```

크레딧과 모델 ID를 확인하기 위한 최소 스모크 시험:

```bat
python -m bench.gms_model_bench ^
  --models gpt-5-nano ^
  --runs 1 ^
  --case-id all-fields-urgent ^
  --confirm-live ^
  --output-dir results\gms-bench-smoke
```

스모크 결과에서 기준 모델의 요청·스키마 검증 성공 여부를 확인한 후 후보 모델을
하나씩 추가한다. 사용할 수 없는 모델 ID 때문에 불필요하게 많은 요청을 보내지 않는다.

```bat
python -m bench.gms_model_bench ^
  --models gpt-5-nano,gpt-5.4-nano ^
  --runs 2 ^
  --confirm-live
```

특정 모델 ID가 틀렸다면 GMS에서 확인한 ID만 명시적으로 다시 실행한다.

```bat
python -m bench.gms_model_bench ^
  --models 실제-GMS-모델-ID ^
  --runs 1 ^
  --confirm-live ^
  --output-dir results\gms-bench-corrected
```

## 6. 결과 파일

| 파일 | 내용 |
|---|---|
| `gms-bench-raw.json` | 문장·모델·회차별 정답, 추출값, 지연, 토큰, 오류 |
| `gms-bench-summary.json` | 실행 메타데이터와 모델별 요약 |
| `gms-bench-summary.csv` | 발표 자료와 표 작성에 사용할 모델별 요약 |

메타데이터에는 실행 ID, UTC 실행 시각, 데이터셋 경로, 모델 목록, 반복 횟수,
프롬프트 SHA-256 축약값, GMS base URL이 기록된다. API 키는 기록하지 않는다.

## 7. 모델 선정 규칙

다음 조건을 모두 만족해야 운영 후보가 된다.

- 위험→안전 오판 0건
- 파싱 성공률 99% 이상
- 슬롯 정확도 90% 이상
- 숫자·이동 가능 여부 정확도는 원본 결과에서 별도 확인하여 95% 이상
- 환각 슬롯 발생률 2% 이하
- 완전 일치 일관성 95% 이상
- 성공 요청 P95 3초 이하

한 번의 20문장 시험은 후보 압축용이다. 최종 선정은 정량 검증 기준의 확장
데이터셋과 실제 STT 출력 입력 시험을 추가한 뒤 확정한다. 가장 큰 모델이나 최신
모델을 자동 선정하지 않으며, 안전 기준을 통과한 모델 중 지연·사용량이 작은 모델을
우선한다.

## 8. 결과 공유 시 주의사항

- `.env`와 GMS 키는 첨부하지 않는다.
- 실제 요구조자 음성·전사문을 모델 비교 데이터로 사용하지 않는다.
- 모델 미지원 오류를 해당 모델의 품질 실패로 해석하지 않고 “GMS 접근 불가”로 분리한다.
- 네트워크 상태와 실행 시각이 다른 결과를 단순 지연 순위로 비교하지 않는다.
- 원본 결과를 검토하지 않은 상태에서 요약 CSV만으로 운영 모델을 확정하지 않는다.
